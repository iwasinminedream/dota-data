# Dota 6962: What Changed

The report was generated automatically on 2026-10-19. The draft covering all changes (1 part) was written by Claude Haiku 4.5; the check against the source data and the final version were done by Claude Opus 5.5 (both read-only). The tables below were calculated without a model.

## Summary

### Highlights

- **The numbers in the `modifierfunction` enum shifted by +1.** `MODIFIER_PROPERTY_MIN_ATTACK_RANGE = 119` was inserted before `MODIFIER_PROPERTY_MAX_ATTACK_RANGE`. As a result, all values from the old 119 through 408 increased by one: `MAX_ATTACK_RANGE` 119→120, `MODIFIER_EVENT_ON_ATTACK_LANDED` 200→201, `ON_TAKEDAMAGE` 214→215, `MODIFIER_PROPERTY_TOOLTIP` 243→244, `IGNORE_FORCE_ATTACK_TARGET` 408→409, `MODIFIER_FUNCTION_LAST` 409→412. `MODIFIER_EVENT_ON_TREE_PLANTED = 410` and `MODIFIER_EVENT_ON_DAMAGE_HP_LOSS_SELF = 411` were added at the end. This is visible when comparing `previous-dump.txt` with `dumper/dump`. The shift does not appear in api-changes.txt: the comparison tool does not track value changes, and the changed section of the changelog is empty.
- **The numbers in `DOTASlotType_t` shifted by +9.** After `DOTA_LOADOUT_TYPE_ABILITY_ULTIMATE_PERSONA_1 = 67`, `ABILITY_EFFECTS_1..9_PERSONA_1` (68–76) were inserted. Everything after them increased by 9: `VOICE_PERSONA_1` 68→77, `PERSONA_1_END` 68→77, `COURIER` 70→79, `HUD_SKIN` 75→84, `NONE` 102→111, `COUNT` 103→112.
- **Venomancer's Plague Wards were reworked.** The five units `npc_dota_venomancer_plague_ward_1..5` were removed and replaced by a single `npc_dota_venomancer_plague_ward`. The parameters are now set through the ability's AbilityValues: `ward_max_health` 150/250/350/450, `ward_base_damage` 16/24/32/40, `ward_damage_spread` 2, `ward_gold_bounty_min/max` 10/14/18/22, `magic_immune` 1. The old `ward_hp_tooltip`, `ward_damage_tooltip` and `ward_multiplier` were removed. The server code confirms this: near the place where the name `npc_dota_venomancer_plague_ward` is used, it reads `ward_max_health`, `ward_base_damage`, `ward_damage_spread`, `ward_xp_bounty`, `ward_gold_bounty_min/max`, `magic_immune` and `ward_model_scale`.
- **Necronomicon:** the recipe is now `item_staff_of_wizardry + item_belt_of_strength` instead of two `item_sobi_mask` and `item_belt_of_strength`. Mana regeneration (`bonus_mana_regen` 2/3/4) was replaced by intelligence (`bonus_intellect` 15/20/25). Price: 2050→2700, 3950 and 5200 for levels 1–3.
- **Tidehunter's Arcana "Maw of the Megalodon".** Two styles are unlocked through mini-games:
  - "The Hammer of Maelrawn" — Ravage hitting 3+ heroes, up to 25 points per game;
  - "Unfathomable Hunger" — eating fish that drops from enemy heroes, up to 20 points per game.

  `modifier_tidehunter_arcana` and the `DOTAHUDTidehunterArcana` panel were added. libserver.so contains the item class `CDOTA_Item_Tidehunter_Fish` / `item_tidehunter_fish`, the model `tidehunter_fish_pickup.vmdl`, the message `CDOTAUserMsg_TidehunterArcanaProgress_Fish` and the console variables `dota_tidehunter_arcana_*` (default 20 / 25 / 3 / 1, flags sv and cheat).
- **Treasure "Trove of Terror" (Monster Hoard 2026)** with 17 sets (`DOTA_Set_*`), including Drow Ranger's Arcana "Dread Retribution" and the Tidehunter Arcana. According to the localization, it has bonus rewards for the number of chests opened, Bad Luck Protection, and gifting only within 30 days after opening. A Roshan cosmetic, a Tormentor cosmetic and "Hero Base" slots for 6 heroes were also added.
- **The server limits incoming network traffic more strictly.** A new `net_limit_sv_*` family was added, the CPU time limits were renamed, and they have new default values (details below).

### New properties and methods: what they do

**`MODIFIER_PROPERTY_MIN_ATTACK_RANGE` (119) / `CDOTA_Modifier_Lua:GetModifierMinAttackRange()`**
- What it does. The description in the dump is only the function name "GetModifierMinAttackRange". The property sits right before `MAX_ATTACK_RANGE`. Hence the assumption: it is the lower bound of attack range, a pair to `MAX_ATTACK_RANGE`, which limits it from above. But another interpretation is possible: "do not attack targets closer than X". I could not distinguish between them from the code.
- Evidence:
  - In the HasFunction test (`modifier_properties.json`) it is `true`; in changelog 6962 the value changed from false to true. So the engine calls this Lua function.
  - libserver.so contains the string `GetModifierMinAttackRange`. One wrapper (0x42d1b50) references it. It is built the same way as the neighboring wrapper `GetModifierMaxAttackRange` (0x42d1b80): both call the common helper 0x42cf380. So the Lua method call is wired in the same way as for MAX.
  - I could not find where the value is used in the range calculation: no code references the string `MODIFIER_PROPERTY_MIN_ATTACK_RANGE`, and there are no exported symbols. The string `attack_range_min` in libserver.so belongs to abilities (Winter Wyvern and others), not to this property.
  - The property does not appear anywhere in KV or the localization.
- How to use it: add it to `DeclareFunctions()` and return a number. In `api.json` the method's return type is given as `nil`; this is a typing inaccuracy, and in practice a number must be returned. How exactly it affects range, check in the tools: compare `GetAttackRange()` before and after.
- Reliability: that the engine calls the function is high. The meaning of the value is medium or low: the conclusion is based only on the name.

**`MODIFIER_EVENT_ON_TREE_PLANTED` (410) / `OnTreePlanted()`**
- What it does. By name, it is a tree-planting event, a pair to `ON_TREE_CUT_DOWN`. The description in the dump is only "OnTreePlanted", and the signature has no arguments.
- Evidence:
  - HasFunction is `false`, and `api.json` has `"broken": true`.
  - The string `OnTreePlanted` is present in libserver.so, but no code references it (0 places). For comparison: `OnTreeCutDown` is referenced by the Lua wrapper 0x42d26f0.
- Conclusion: this event is not called from a Lua modifier. Built-in C++ modifiers may use it; this has not been verified.
- Reliability of the conclusion "does not work in Lua" is high.

**`MODIFIER_EVENT_ON_DAMAGE_HP_LOSS_SELF` (411) / `OnDamageHPLossSelf()`**
- What it does. By name, it is a variant of the existing `MODIFIER_EVENT_ON_DAMAGE_HPLOSS` (317) that triggers only for the modifier's owner itself. This is a conclusion based on the name alone.
- Evidence: HasFunction `false`, `"broken": true`; no code references the string `OnDamageHPLossSelf` in libserver.so.
- For Lua modifiers: it is not called, use `MODIFIER_EVENT_ON_DAMAGE_HPLOSS` (HasFunction `true`).
- Reliability is high (for the conclusion "is not called").

**`DOTA_ABILITY_BEHAVIOR_DIRECT_KEYBIND` = 9007199254740992 (2^53)** — in Lua, Panorama and the engine enum.
- What it does. It marks additional abilities that can be assigned a separate hotkey.
- Evidence:
  - In KV this flag has been present since version 6933 on 17 abilities: 10 Invoker spells (`invoker_cold_snap`, `invoker_ghost_walk`, `invoker_tornado`, `invoker_emp`, `invoker_alacrity`, `invoker_chaos_meteor`, `invoker_sun_strike`, `invoker_forge_spirit`, `invoker_ice_wall`, `invoker_deafening_blast`), `kez_falcon_rush`, `kez_talon_toss`, `kez_shodo_sai`, `kez_ravens_veil` and the three `largo_song_*` songs. These are all abilities that are not permanently on the panel.
  - The localization contains `dota_settings_additional_abilities` ("Additional Abilities") and a new tooltip `dota_settings_additional_abilities_tooltip`: "Show this Hero's additional abilities to bind hotkeys directly to them".
  - Both libraries contain a string with the flag name, but no code references it directly.
- What is new in this version: the flag is only exported to the script enum.
- Whether it will do anything for custom abilities is unknown. The setting is organized per hero, and it has not been tested on custom heroes.
- The value 2^53 cannot be checked with 32-bit bitwise operations (`&` in JS, `bit.band` in Lua 5.1) — the same problem as with `FORCE_KEYBIND` and other high flags.
- Reliability: the purpose is medium (based on KV and localization, without code).

**`GameUI.GetAbilityNameLocalizedForAbilityID(nAbilityID: number): string`** (Panorama)
- What it does: returns the localized name of an ability by its numeric ID. The description in the dump: "Get the localized version of an ability's name by ability ID".
- In libclient.so the function is registered in the GameUI table next to `GetHeroNameLocalizedForHeroID`, `GetUnitNameLocalized` and `IsAbilityDOTATalent`.
- Whether it works for custom abilities without an ID is unknown.
- Reliability: high for standard abilities.

**`WriteCompositionLayerJPEG(_arg_1: string, _arg_2: string, _arg_3: number, _arg_4: number): void`** — on all 36 panel classes.
- By name: writes a panel's composition layer to a JPEG; the paired method `WriteCompositionLayerPNG` now takes two string arguments.
- In libclient.so the method is registered among the base Panel methods, next to `SetCompositionLayerTextureName` and `WriteCompositionLayerPNG`.
- The purpose of the arguments is not specified in the dump (the names are `_arg_N`). Apparently they are a path and quality or size parameters, but that is a guess.
- Reliability: the purpose is low or medium; in the game UI it looks like a debugging tool.

**New panel attributes:**
- `unitindex` on `DOTAUIEconSetPreview` — description in the dump: "Specify which unit index to use, like if we want an alternate Courier form";
- `focus-range-size` on `Carousel` — no description;
- `renderdecals`, `rendershadows`, `rendervolumetricfog` — on the new panel `GameMonitorPanel` (base `RenderPanel`). `rendershadows` already existed on `DOTAScenePanel`.

**Other new constants:**
- `ACT_DOTA_DEFEAT_STATUE`, `ACT_DOTA_CHANNEL_STATUE` — new animations in the `*_STATUE` series. The numbers 1795/1796 are unreliable: ACT values in this section of the dump get shuffled even between two dumps of the same build (`dump-noise.md`), and neighboring ACTs changed (for example, `ACT_DOTA_CAST3_STATUE` 1797→1794). Use the names.
- `AE_STATE_CHANGE_IN_PROGRESS = 1` — an animation event constant (AE_*). The meaning is unclear; I did not look in the code.
- `FIELD_xxxAvail1/2` replaced `FIELD_MATRIX3X4_WORLDSPACE` and `FIELD_VMATRIX_WORLDSPACE`: by name, these are freed-up field types.

### For custom game developers

**What may break addons:**
- **The `modifierfunction` and `DOTASlotType_t` numbers.** Code that stores values as numbers rather than constant names will break: Lua, Panorama JS, generated tables. Ordinary `DeclareFunctions()` with global names will not be affected. If a TypeScript build inlines enum values as numbers, it needs to be rebuilt with updated types.
- **The units `npc_dota_venomancer_plague_ward_1..5` were removed.** `CreateUnitByName` with these names will no longer work. Overrides of the ward's stats through unit KV no longer take effect: the game takes HP, damage and bounty from the AbilityValues of `venomancer_plague_ward`. The keys `ward_hp_tooltip`, `ward_damage_tooltip`, `ward_multiplier` were removed, so `GetSpecialValueFor` for them will return 0. The talent tooltip key `special_bonus_unique_venomancer` now refers to `{s:bonus_ward_base_damage}`. libserver.so still contains one more reference to the format `npc_dota_venomancer_plague_ward_%d` — next to `modifier_greevil_miniboss_casting`, apparently in an event mode.
- **`crystal_maiden_freezing_field`:** the key `explosion_interval` was removed. `explosion_interval_tooltip` (0.1) and `num_explosions` (100) appeared, and the description now uses `%num_explosions%`. The server code near Freezing Field reads `num_explosions`; there is no string `explosion_interval` in libserver.so. Apparently the interval is computed — this is an inference, not a verified fact.
- **`CDOTA_Ability_Aghanim_Spear` and `LaunchSpear(target, start)` were removed.** There are also no strings with these names in libserver.so.
- **`SpawnHeroInScenePanelByHeroId`** (`DOTAScenePanel`, `DOTAParticleScenePanel`): the third argument is now a string, not a number. The meaning of the argument is not specified in the dump.
- **`WriteCompositionLayerPNG`** now requires two arguments. Calls with the old single-argument signature will most likely fail with an error: the handler of this method contains the string "%s requires %d arguments; only %d given".
- **Network limits on incoming messages from clients** (descriptions from convars.json):

  | Variable | Value | What it limits |
  |---|---|---|
  | `net_limit_sv_recv_chan_msgs_per_frame` | 500 | messages in one network frame; exceeding it disconnects the client |
  | `net_limit_sv_recv_chan_buffer_messages` | 1000 | receive queue; was `sv_recvbuf_messages` 1024 |
  | `net_limit_sv_recv_max_frame_size_kb` | 64 | frame size; was `net_limit_sv_recv_max_message_size_kb` 32 |
  | `net_limit_sv_listen_*` | 3 KB / 16 KB / 4 messages | connections that do not yet have a netchan |
  | `net_message_size_enforce` | 1 | 0 — ignore, 1 — warn in the log, 3 — reject |

  The CPU time limits were renamed: `sv_net_client_message_process_time_ms_*` → `net_limit_sv_message_process_time_ms_*`. Values: drop_burst 200, warn_burst 50 (unchanged), drop_rate 20→100, warn_rate 5→150.

  If Panorama sends `GameEvents.SendCustomGameEventToServer` in large volumes, check that clients are not being disconnected. The connection to custom events is my inference from the descriptions, not verified.

**KV changes.** New AbilityValues keys with the value 0; what they enable is unknown:
- `earthshaker_fissure`: `free_pathing_application_radius` 150→0 and a new `free_pathing_all_allies` 0;
- `gyrocopter_flak_cannon`: `additional_targets`, `proc_attack_modifiers`;
- `hoodwink_sharpshooter`: `pierce_units`, `pierce_hero_damage_reduction_pct`;
- `legion_commander_overwhelming_odds`: `shield_counts_non_hero_damage`.

Strings with these names are present in libserver.so, but some of them are also used by other abilities. `item_consecrated_wraps` has a new key `damage_must_be_player_owned_or_roshan` = 1 — this matches the already existing Note0 tooltip.

**Heroes.** For 15 heroes only `ItemSlots` (cosmetic slots) were changed:
- new `ability_effects_N` slots for Shadow Shaman, Death Prophet, Broodmother, Treant, Undying, Nyx Assassin, Legion Commander, Terrorblade, Oracle, Marci and Primal Beast;
- `ability_effects_N_persona_1` for Anti-Mage and Pudge;
- `hero_base` for Drow Ranger, Tidehunter, Nyx Assassin, Legion Commander, Terrorblade and Pudge;
- for Shadow Shaman — `LoadoutPreviewMode "hex_model"`.

The slot indices shifted: `hero_effigy` and `persona_selector` moved to new numbers. This matters if an addon relies on slot numbers. Tidehunter also gained `AttackSpeedActivityModifiers fast = 150`.

**Panorama.** New panels: `DOTADBPopupPersonalOffer`, `DOTAHUDTidehunterArcana`, `DOTATreasureContentsList`, `DOTAVisualNovelDebugPage`, `GameMonitorPanel`. For custom games, all of them are internal.

- **Useful for map debugging:**

  - `create_explosion_damage` — an explosion with physical force; cheat;
  - `nav_edit_draw_navlink_ranges`, `navspace_create_water_surface_connections`.
- **Navigation:** 8 `nav_smooth_*` were added (arrival, navlink_entry, handle_scale, draw_arrival_calc). 34 debug `nav_*` were removed: `nav_drag_*`, `nav_draw_*`, `nav_select_*`, `nav_show_*`, `nav_test_*`, `nav_smooth_spring_timestep_*`.
- **Experimental NPC controller:** `dota_use_experimental_npc_controller_{creeps_only,heroes_only,pet,roshan_only}` (sv, default false); `dota_debug_npc_controller_entity_index` was removed.
- **Removed:** `screenmessage_show`, `screenmessage_notifytime`, `cl_screenmessage_notifytime`, `r_draw_overlays`, `dota_video_config.setting.*` (5), `cl_demo_steadycam_*` (4), `lightquery_debug_*`, `tv_demo_starttick`, `wind_system_debug_volumes` and others.
- **Other:**
  - GOTV encryption: `tv_encryptdata_key(_pub)`, `cl_decryptdata_key(_pub)`;
  - `cl_frame_perf_sample_buffer_max`, `sv_frame_perf_sample_buffer_max`;
  - `dota_hero_grid_show_persona_portraits`;
  - client-side `dota_madness_color(_cb)`, `dota_health_bar_max_health_cap`, `dota_bits`, `dota_ui_language_storage` — no descriptions, meaning unclear;
  - graphics: `r_colorblindsim_*` (6), `vulkan_*`, `r_vma_defrag_threshold_mb`, `rtx_*`;
  - Steam Audio: 21 new `snd_steamaudio_*`.

**Localization:** +234 −2 ~19. Almost all of it is cosmetics and the treasure. Of the rest: Plague Ward (keys renamed, see above), Freezing Field, and the labels "Custom Ability Effects" and "Immortal Ability Effects" (now plural).
