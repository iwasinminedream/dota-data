# Dota 6979: What Changed

The report was generated automatically on 2026-11-19. The draft of all changes (parts: 2) was written by Claude Sonnet 5.5. The verification against the source data and the final version were produced by Claude Sonnet 5.5 (read-only access). The tables below were calculated without a model.

## Summary

### Highlights

- **Nyx Assassin balance (KV data, reliable).** Base hero health regeneration 1 → 2. In `nyx_assassin_mana_burn`, the `max_mana_as_damage_pct` parameter rose from `20 25 30 35` to `25 30 35 40`. In `nyx_assassin_vendetta`, `bonus_damage` changed from `300 380 460` to `300 400 500`. The talent bonus `special_bonus_unique_nyx_vendetta_damage` stayed at `+50`.
- **Fractional values in item modifiers (schema and code, reliable).** The parameters of six modifier classes changed from `int32` to `float32` in the schema of both libraries. Affected are Eye of Skadi (slows), Orb of Corrosion, Witch Blade, Serrated Shiv, Stormcrafter and Safety Bubble. As a result, such values are no longer truncated to an integer. No new numbers appeared in the item KV.
- **Kunkka: Tidebringer got a second visual effect (code and VPK, moderate reliability).** `CDOTA_Modifier_Kunkka_Tidebringer` now creates one more particle, `kunkka_tidebringer_aoe.vpcf`. Six new `kunkka_tidebringer_aoe*` particles appeared in the VPK. The damage, slow and armor-piercing logic did not change.
- **Game tips changed.** Universal heroes get 0.45 damage per point of any attribute instead of 0.7. The Roshan drop is described differently: from the second death Roshan's Banner drops, and after the third also Refresher Shard and Cheese. "Pierces Debuff Immunity" was removed from the Eye of Skadi tip. The numbers and flags in KV did not change, so this is a text edit, not a confirmed mechanics change.
- **No new API.** The dump shows only `ACT_DOTA_CAST5_STATUE = 1807`, which is dumper noise. There are no new methods, events or modifier properties.
- **The rest of the 103 functions in `libserver.so` is relinking.** It is mostly a shift of tables and addresses. Techies and the "Shiva's Guard / River Painter" pair look like function-matching artifacts rather than a change of logic (details below).

### New properties and methods: what they do

This build has no new properties, Lua methods, events or Panorama API. `api-changes.txt` contains a single line:

- **`ACT_DOTA_CAST5_STATUE` = 1807 (GameActivity_t).**
  - This is noise. The control dump of the same build (`dump-noise.md`, section `cl_script_reload`) also unstably contains and loses this name.
  - Along with it, `ACT_DOTA_CAST_FENCE`, `CYCLONE`, `IMPALE`, `TORRENT`, `VOODOO_REST`, `RADIANT_CREEP_HAMMER`, `RELAX_*`, `SPWN`, `LOADOUT_STATUE`, `muerta_debut_satyr_*` and `radiant_melee_mars_shieldbash` are "renumbered", and `ACT_DOTA_RUN_ALT` appears in the control dump.
  - This name should not be used in addons. The numeric values of `ACT_DOTA_*` are unstable in this build.

The `permit_illusion_recycling` key is not a new API:

- **`permit_illusion_recycling`.** This is an existing field of the `CreateIllusions` table (`permit_illusion_recycling: bool | nil`), described in `files/vscripts/api-types.json` and in changelog 6966.
  - In this build `CDOTA_Modifier_Morphling_Replicate_Echo_Source` (0x45100e0) additionally reads this value from KV with a default of 0. This is visible in the diff: +1 call after `duration`.
  - The conclusion about the field's purpose is based on its name, as "allow reuse of illusions". This is a guess. The key was not found in the `morphling_replicate` KV or in the localization, so reliability is low.

### For custom game developers

- **Modifier field types changed to `float32`.** This is visible in the `libclient.so` and `libserver.so` schema, with 2 entries per class:
  - `CDOTA_Modifier_Item_SerratedShiv.proc_chance`;
  - `CDOTA_Modifier_Item_Skadi_Slow`: `cold_slow_melee`, `cold_slow_ranged`, `cold_attack_slow_melee`, `cold_attack_slow_ranged`;
  - `CDOTA_Modifier_Item_Stormcrafter.damage`;
  - `CDOTA_Modifier_Item_Witch_Blade_Slow.slow`;
  - `CDOTA_Modifier_Orb_Of_Corrosion_Debuff`: `corruption_armor`, `heal_reduction`, `slow_melee`, `slow_ranged`;
  - `CDOTA_Modifier_Safety_Bubble.shield`.

  Why: all these `AbilityValues` blocks have the multipliers `apply_effectiveness: 1` (Skadi, Orb of Corrosion, Witch Blade, `proc_chance` of Serrated Shiv) or `apply_curio_bonus: 1` (`shield` of Safety Bubble, `damage` of Stormcrafter). Scaling by these multipliers gives fractional results, while the field used to store an integer.

  This is a conclusion from KV and code, with medium reliability. I did not decode the names of the multipliers from the code.

  For addons: if a custom game uses these items and such multipliers, the resulting slows and damage may differ slightly from before. There are no breaking changes in the Lua signatures.
- **KV files.** Only `npc_dota_hero_nyx_assassin.txt` changed. If you replace or override the Nyx hero in an addon, you need to carry over the new numbers yourself.
- **`heroes.herolist_c`** changed; the reason is not clear from the data. The diff of `scripts/heroes.herolist_c` is not shown in `tracking-diff.txt`.
- **Console variables, Panorama and events.** No changes in the data.
- **What may break addons.** There are no direct sources of breakage. It is worth rechecking item balance with fractional multipliers, and the Nyx hero if it is used in a custom game.

### Game code changes

In total 24 functions changed in `libclient.so` and 103 in `libserver.so`. This is more than 60, so they are grouped below. The full list is in `so-query.py funcs libserver.so` and `funcs libclient.so`.

**1. int → float conversion in item modifiers (the most significant, high reliability per the diff).**

In all cases the KV value is read with the float variant of the getter and stored via `movss`, and the reading functions use `movss` instead of `cvtsi2ss`. The classes are the same as in the schema.

- **Eye of Skadi** (`CDOTA_Modifier_Item_Skadi_Slow`):
  - The loader in `libserver.so` is 0x4eb1bc0 and the `libclient.so` version is 0x4df1880.
  - `cold_attack_slow_melee`, `cold_attack_slow_ranged`, `cold_slow_melee`, `cold_slow_ranged` are read (fields 0x1b00, 0x1b04, 0x1af8, 0x1afc).
  - `restoration_reduction` (0x1b08) is still read at the end, via a tail call. The earlier assumption that the field "disappeared" was an artifact of a truncated diff.
  - Value getters: 0x4ea5be0, 0x4ea5c40 (`libserver.so`), 0x4de0120, 0x4de0190 (`libclient.so`).
  - The same code reads `modifier_item_skadi_slow` from functions attributed in the dump to `Orb_Of_Corrosion_Debuff`: 0x4fa54c0, 0x4fa7cf0, 0x4ecb1f0, 0x4ecd300. This is most likely shared code (folding). The "minus" sign of the slow is preserved via `xorps`.
  - Functions 0x4fa6270 and 0x4ecb150 read field 0x1af8 for `modifier_desolator_buff` / `modifier_stygian_desolator_buff`. This is also folding with a shared getter; the field became float.
- **Orb of Corrosion** (`CDOTA_Modifier_Orb_Of_Corrosion_Debuff`):
  - 0x4fb28e0 and `vfunc#79` in `libclient.so` (0x4ed6e40).
  - `corruption_armor`, `heal_reduction`, `slow_melee`, `slow_ranged` became float.
  - In `libclient.so` an expanded branch with `AbilityManaCost` / `AbilityHealthCost` was added for `corruption_armor` (287 → 1027 bytes).
- **Witch Blade** (`CDOTA_Modifier_Item_Witch_Blade_Slow`):
  - `OnCreated` (0x5018920 and 0x4f3ef40), `slow` is float.
  - Getters 0x500b320 and 0x4f2e340: `neg` + `cvtsi2ss` were replaced with `xorps` with a sign constant.
- **Serrated Shiv** (`CDOTA_Modifier_Item_SerratedShiv`):
  - `OnCreated`: 0x4fe5b60 and 0x4f0ebe0. `proc_chance` is float.
  - Chance roll (0x4feb180): the value is read as float, passes through an additional call (+1 call) and is truncated by `cvttss2si` to int. Then comes a chance-check call with the constant 0x47. Result: the fractional chance (30 × effectiveness) is still rounded down to a whole percent at the roll itself.
  - A getter function 0x4f02430 was added in `libclient.so`.
- **Stormcrafter** (`CDOTA_Modifier_Item_Stormcrafter`):
  - `OnCreated` 0x5001210 and `OnIntervalThink` 0x4ffd5b0. `damage` (0x1b04) is float.
  - In `OnIntervalThink` this is the only change: `movss` instead of `cvtsi2ss`.
  - In KV `damage` = 90 with `apply_curio_bonus`.
- **Safety Bubble** (`CDOTA_Modifier_Safety_Bubble`):
  - `OnCreated` / `OnRefresh` (0x4fe6df0): `shield` is float.
  - In the branch where the value is converted to an integer, an inline `floor` was added (constants: nan mask, 8388608, 1).
  - Function 0x4fe0240 (from `vfunc#97`): absorption is now computed in float, via `comiss` / `subss`. Previously the sum `(int)x + [0x1af8]` was compared with `shield` as int.
  - In KV `shield` = 125 with `apply_curio_bonus`.
  - In `libclient.so` 0x4f023a0 was added and 0x4f024e0 removed, probably a rewritten getter.
  - Effect: the shield is calculated without truncation to an integer. This is a conclusion from the code, with medium reliability.

**2. Kunkka — Tidebringer** (`CDOTA_Modifier_Kunkka_Tidebringer::vfunc#97`, 0x44e3f60; moderate reliability).

- The string `kunkka_tidebringer_aoe.vpcf` was added: a second particle instance is created using the same template as `kunkka_spell_tidebringer.vpcf`. The same fields 0x1afc, 0x1b00 and 0x1b04 (cleave widths and distance) are used. A virtual call of slot 3 (+0x18) was added.
- Direct calls 64 → 73, instructions 412 → 446, stack 0x2d8 → 0x2e8.
- The rest of the code (the `cleave_*` fields, `movespeed_slow_duration`, `pierces_armor`) did not change.
- What exactly the particle draws is unclear from the diff. The VPK file names (`_front`, `_normal`, `_normal_quick`, `_splash`, `_spray`) hint at a visual cleave splash. This is a guess based on the names.
- Five Ghost Ship functions (`AddActiveCannonball`, `CreateHitListForCannonballVolley`, `FireCannonsFromLocation`, `RemoveActiveCannonball`, `CDOTA_Ability_Kunkka_GhostShip::vfunc#371`) differ only by the source line number +5 in the assert call. This is a line shift in the file; the logic did not change.

**3. Morphling.**

- `Replicate_Echo_Source` (0x45100e0): reading of `permit_illusion_recycling` with a default of 0 was added (+1 call). What is then done with the result is not shown by the diff.
- `Morphling_Syntropy` (0x44b5fa0, `modifier_morphling_syntropy_slow`): a repeated check of the second handle (field 0xd0 with the same pattern as 0xcc) was added, with the condition `byte [ent+0x5d1] == 3`. Instructions 118 → 143. All that is visible is that the check is now done for both handles. What the value 3 in field 0x5d1 means and which behavior exactly changed is unclear from the diff. Reliability is low.

**4. Anti-Mage `Mana_Overload::OnSpellStart`** (0x451b160): the inline handle resolution in the loop was replaced with a function call (59 → 60 calls). Most likely a refactoring. Reliability is low.

**5. Techies.** There is no behavior diff here.

- 0x4d28540 shrank from 9275 to 2795 bytes. 0x4d26650 (7338 bytes) was added. 0x4d69620 (882 bytes) was removed.
- According to `so-query func new libserver.so 0x4d26650`, this is not a working function but a set of uniform thread-safe static variable initializers. The pattern "flag check → structure reset → registration call" with the constant `0x…09…` repeats. The sticky bomb and stasis trap strings are adjacent data.
- Conclusion: a redistribution of function boundaries between builds, not a change of Techies logic. Reliability is medium.

**6. Swap of Shiva's Guard Thinker / River Painter** (0x4eb30e0 and 0x4eb3520).

- `so-query func old libserver.so 0x4eb2f60` shows that in the old build this address holds code with `paint_duration` and `RiverPaint.Cast` (classes `RiverPainter..RiverPainter4` and 3 more), while in the new build the code at this address is `blast_*`.
- This is function matching by order, not a change of item logic. The old `blast_*` code (`xref old ... blast_debuff_duration`) lies at the neighboring address 0x4eb34f9. Reliability is medium.

**7. Other.**

- `CDOTA_Modifier_Item_VindicatorsAxe::OnCreated` (0x501a040) and `CDOTA_Modifier_Item_Skypiercer::OnCreated` (0x4eb2240): the getters changed shape (int getter with a default value ↔ pointer variant). The schema did not change. Looks like a refactoring.
- A `libclient.so` group (Naginata, Ocean Heart, MetamorphicMandible_Active, Misericorde, OgreSealTotem_Active, Nothl_Sigil, Occult_Bracelet, MaskOfDispair, Mechanical_Arm, Mind_Breaker, Orb_Of_Frost, Orb_Of_Frost_Debuff):
  - Function sizes change (1251 → 495, 1709 → 963, etc.). An expanded inline block with `AbilityManaCost` / `AbilityHealthCost` is moved within them.
  - Judging by KV, this block is the calculation of values with multipliers (`apply_effectiveness` / `apply_curio_bonus`) together with the owner. But its movement between parameters looks like a different compiler inlining decision.
  - There are no direct signs of a balance change.
- 39 functions of `libserver.so` (0x3d860c0…0x3eca460, KV3 walkers and schema switch functions):
  - They differ only by the jump table address / the network type name string (`CHandle`, `GameTime_t`, `VectorWS`, `CUtlVector`, `HitGroup_t`, etc.) and a reference to `.rodata`.
  - This also includes 0x3bf7540, 0x3c27620…0x3c29c60, 0x3c6a420, 0x3cc00d0, 0x3d22ce0.
  - This is relinking. 0x3e6ee90 was added; 0x3e6ebf0, 0x3e6ed20, 0x3e6eec0 were removed.
- 0x5c15010 (2695 bytes, unnamed): one block was moved, stack slots were shifted. The logic is unclear, most likely compiler reordering.
- Copies of existing code (12 in each library, `vfunc#50` of `Pupils_gift`, `PyrrhicCloak`, `Recipe_Quickening_Charm`, `Seer_Stone`, `SerratedShiv`, `Angels_Demise`, etc.) are linker folding, not changes.
