# Dota 6963: what changed

The report was generated automatically on 2026-10-19. The draft covering all changes (1 part) was written by Claude Haiku 4.5, and the verification against the source data and the final version by Claude Opus 5.5 (both with read-only access); the tables below were computed without a model.

## Summary

### Main points

- **No API changes.** The file `api-changes.txt` is empty. The `.so` files have no added or removed strings or exports (+0 −0). Commit 6963 in dota-data did not touch `abilities.json`, `units.json`, `heroes.json` or localization. Only the machine code of `libserver.so` and `libclient.so` changed: 2 functions in the client and 11 on the server. The rest is the linker merging identical code.
- **Tinker, Keen Conveyance (`tinker_keen_teleport`): the teleport target selection was reworked** on the server and in the client.
  - A new target filter appeared: a virtual unit method (slot 347 on the server, 354 in the client). It was not possible to establish which method this is.
  - The server selects the target in this order. First, the unit that was clicked, if the cast point is no farther than 100 from it (a building is accepted without this condition). Then the allied building closest to the point within a radius of 900. Then the nearest valid ally.
  - The same 900 rule appeared in the client preview (constant 810000 = 900²).
- **Legion Commander, Duel.** If an illusion or a non-hero dies in a duel, the duel is now removed from both participants without a reward. Previously the function returned immediately in this case and did nothing.
- **Hoodwink, Decoy.** On Sharpshooter, the decoy illusion now additionally has an ability method called, slot 292. This is the same method that Rearm uses to reset the cooldown. The decoy can most likely now start Sharpshooter even if it is on cooldown for Hoodwink herself. This is a hypothesis, with medium confidence.
- **Dawnbreaker, Solar Guardian.** Only the call for statistics and quest tracking (event 0x33e) changed: any NPC target is now passed into it, not just a real hero. Damage and healing did not change.
- **Rearm, Roshan, Tormentor, Ember Spirit, Sniper — recompilation without logic changes.** The list of items that Rearm does not refresh is the same.

### New properties and methods: what they do

There are no new modifier properties, events, Lua or Panorama methods, behaviors, or ability flags.

- **Basis:**

### For custom game developers

- **API.** Nothing was added, removed or renamed. Addons will not break because of the API.
- **The `ACT_*` constants in the dump are unreliable.** Between 6962 and 6963, numeric values "changed" in `dumper/dump` and `files/vscripts/enums.json`, for example:
  - `ACT_DOTA_CAST5_STATUE` 1798→1808;
  - `ACT_DOTA_CYCLONE` 1799→1810;
  - `ACT_DOTA_IMPALE` 1800→1811;
  - `ACT_DOTA_CAST_FENCE` 1811→1800;
  - `ACT_DOTA_DISABLED_END` 1792→1797;
  - `ACT_DOTA_DEFEAT_STATUE` 1795→1794.
  
  The current dump has no `ACT_DOTA_TORRENT`, although the previous one does. The control dump of the same build (`dump-noise.md`) shows the same jumps in the range 1792–1811 and the disappearance of either `ACT_DOTA_CAST5_STATUE` or `ACT_DOTA_TORRENT`. This is dumper noise, not game changes. Refer to animations by constant names, not by the numbers from the dump or from generated types.
- **Behavior that may affect addons** (this is not API, but the logic of built-in abilities):
  - **`tinker_keen_teleport`.** If your addon relies on this ability for non-standard units, some of them may stop being valid targets: the filter (slot 347/354) returns false for them, and the cast gets `UF_FAIL_CUSTOM` (23). This filter cannot be influenced through Lua. The selection order also changed: a building within 900 of the point now takes priority over a closer creep.
  - **`legion_commander_duel`.** A duel with an illusion ends immediately after its death. If your code expected `modifier_legion_commander_duel` to last until the end of its duration, this has changed.
- **Console variables and events** did not change.

**Tinker — Keen Conveyance (main change)**

- **`CDOTA_Ability_Tinker_Keen_Teleport::CastFilterResultTarget`** (server, 0x4593b30).
  - Added: if slot 347 (`0xad8`) returns false for the target, the result is `0x17` = `UF_FAIL_CUSTOM`.
  - Previously only slot 376 was checked for the target (if true — failure).
  - Target types by level did not change: buildings; with `creep_teleport_level` (2) also creeps; with `hero_teleport_level` (3) also heroes (KV).
  - Confidence: high for the check itself. What this method is has not been established. In `CDOTA_BaseNPC_Building` slot 347 is overridden as `return 1` (the same was true in 6962). The descendant `CDOTA_BaseNPC_Watch_Tower` does not override it. This is not `IsBuilding`: the Panorama wrapper `Entities.IsBuilding` in the client reads the bit `0xe0c & 0x10` rather than calling a virtual method.
- **`C_DOTA_Ability_Tinker_Keen_Teleport::CastFilterResultTarget`** (client, 0x47e0990). The same new check, slot 354 (`0xb10`), failure `0x17`.
- **`CDOTA_Ability_Tinker_Keen_Teleport::OnAbilityPhaseStart`** (server, 0x45f4aa0). The target is searched across the whole map via FindUnits (radius −1) among allies; the units found are sorted by distance to the cast point.
  - **New:** before iterating, GetCursorTarget is taken if it is an NPC (except when the cast point coincides with a special team position within 0.1; what this position is has not been established).
  - **The selection order became:**
    1. The target under the cursor, if it is valid (not Tinker himself, does not pass slot 376, passes slot 347). A building is accepted immediately. Another unit is accepted only if the cast point is no farther than 100 from it (new constant 100).
    2. The first valid building by proximity within 900 of the point.
    3. The nearest valid unit.
  - **Before:** the "building within 900" check already existed, but after it the code still took the nearest valid unit of any type. There was no slot 347 check and no priority for the target under the cursor.
  - Confidence: medium. The logic was reconstructed from the assembly of a large function; the rest of the diff is register changes.
- **`C_DOTA_Ability_Tinker_Keen_Teleport::vfunc#261`** (client, 0x4811a20). The client search for the teleport target for a point, with the strings `creep_teleport_level` and `hero_teleport_level`.
  - Before: the nearest valid ally (the unit under the cursor had priority).
  - Now:
    - the slot 354 filter was added;
    - the nearest building and the nearest unit of any type are remembered separately;
    - if the building is closer than 900 (squared distance < 810000), it is returned, otherwise the nearest unit.
  
  The new constant is `810000` = 900², `−inf` is gone. The client now selects the target by the same 900 rule as the server. Confidence: high.

**Legion Commander — Duel**

Function 0x49fdbe0 is called from `CDOTA_Modifier_Legion_Commander_Duel::vfunc#95`, as well as from handlers with `modifier_dazzle_shallow_grave`, `modifier_skeleton_king_reincarnation_scepter_active` and others. It handles the death of a duel participant.

- **Before:** if the deceased was not a hero (`0xcd4 & 1`) or was an illusion (`0x16d2`), the function exited immediately. The duel modifiers were not removed, and there was no reward.
- **Now:** this check was moved into the "duel interrupted without a winner" branch. There, `modifier_legion_commander_duel` is removed from the partner and from Legion Commander, in the same way as under the already existing conditions (`0x443c8a0() > 0` or slot 426 of the deceased).
- **Why this matters:** in the KV of `legion_commander_duel` there is no `NOT_ILLUSIONS` flag, only `NOT_CREEP_HERO`. This means a duel with an illusion is possible, and its death now ends the duel immediately without `modifier_legion_commander_duel_damage_boost`.
- The strings `modifier_legion_commander_duel_damage_boost` were not "added": they existed before and simply moved within the code.
- Confidence: medium or high.

**Hoodwink — Decoy** (`CDOTA_Ability_Hoodwink_Decoy::OnSpellStart`, 0x4940140)

- For each decoy illusion, its `hoodwink_sharpshooter` is looked up. If the level is ≤ 0, `vfunc 0x7a8(1)` is called. This was the case before as well.
- **New:** immediately after this, ability slot 292 (`0x920`) is called unconditionally.
- Rearm calls the same slot on each ability and item that it refreshes (`if (!slot296) slot292`), including the item in slot 15 (TP). Therefore it is almost certainly a cooldown reset (EndCooldown). The illusion copies the owner's cooldowns, so the likely meaning is that the decoy starts Sharpshooter even if it is on cooldown for Hoodwink. This matches the hint: "creates a decoy illusion that starts aiming … Sharpshooter".
- Confidence: medium. The slot name was inferred by analogy.

**Dawnbreaker — Solar Guardian** (`CDOTA_Modifier_Dawnbreaker_Solar_Guardian_Thinker::OnIntervalThink`, 0x492dcc0)

- Only the call `0x5087df0(hero, target, 0x33e, amount)` changes. This function tracks statistics or quests: it works only for a real hero and iterates over `CEconItemView`.
- **Before:** the target was passed through the "real hero" helper `0x4360730`, that is, null for creeps.
- **Now:** the helper is inlined, and only the "is it an NPC" check remains for the target. This means non-heroes are now passed as well (illusions are still filtered out earlier).
- Damage, healing and evasion did not change. This affects only the tracking.
- Confidence: medium.

**Recompilation, logic unchanged**

- **`CDOTA_Ability_Tinker_Rearm::OnChannelFinish`** (0x45f41c0). Code blocks were rearranged.
  - The exclusion list is the same as in 6962: `item_blink`, `item_black_king_bar`, `item_phoenix_ash`, `item_meteor_hammer`, `item_aeon_disk`, `item_arcane_boots`, `item_sphere`, `item_helm_of_the_dominator`, `item_helm_of_the_overlord`, `item_hand_of_midas`, `item_refresher`, `item_refresher_shard`, `item_renewal_orb`, `item_pipe`, `item_necronomicon` (+ `_2`, `_3`), `item_tome_of_knowledge`, the ability `doom_bringer_devour`.
  - The comparison with `item_black_king_bar` is now done through an inlined `strcmp`. Previously the helper `0x42c49a0` was called, but it is the same `strcmp` with a null check — hence the "−2 strings".
  - Confidence: high.
- **`CDOTA_Unit_Roshan::Spawn`** (0x4614130) and **`CDOTA_Unit_Roshan::vfunc#262`** (0x461bcb0, `"Spectator.RoshanFightToggle"`). The network field change mark (`0x1ca8`, `0xb3c`) was inlined and the handle checks were rearranged. Confidence: high.
- **`CDOTA_Unit_Miniboss::vfunc#128`** (0x462dde0, Tormentor death). The same inlining of the network mark (`0x38`). The "removed ~190 instructions" are a neighboring function (hash table insertion, MurmurHash2 with seed `0x3501a674`). Previously it was considered part of this function, and now it is separated out: it is a "copy of existing code" 0x462e7c0 (761 bytes); hence also 219999 → 220000 functions. Confidence: high.
- **Function 0x4642be0** (`"CDOTA_Ability_Sniper_Concussive_Grenade"`). Static class registration in the type schema: name hash with seed `0x31415901`, size `0x860` unchanged. The compiler inlined the MurmurHash step (`0x5bd1e995`, `0x2af99bb2`). It does not affect the ability. Confidence: high.
- **`CDOTA_Ability_EmberSpirit_Activate_FireRemnant::vfunc#371`** (0x492c920). Setting of the remnant handle (`0x894`) was inlined: the index and serial number are computed in place instead of via a call, and the "no entity" branch writes −1. Confidence: high.
- **Copies of existing code** (8 in the client, 15 on the server: `vfunc#49` of Sniper, Roshan, Witch Doctor and others) are merging of identical code, not changes.

### Binaries

- Only `dota-bin/libserver.so` (+704 bytes of code) and `dota-bin/libclient.so` (+256 bytes) changed. The sizes of both are unchanged (126.6 and 146.9 MB). Strings and exports +0 −0. The engine and the other libraries did not change (`so-query libs`).
- This is a targeted gameplay patch: Keen Conveyance target selection was reworked (server and client in sync), the end of Duel was fixed, and Decoy's Sharpshooter was probably fixed, and the passing of the target into Solar Guardian's statistics tracking changed. The rest are side effects of recompilation (inlining, block reordering, function boundaries).
- Behind these edits there are no API changes; network classes and KV did not change.
