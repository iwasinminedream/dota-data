# Dota 6969: что изменилось

Отчёт создан автоматически 2026-10-27. Черновик по всем изменениям (1 частей) — Claude Haiku 4.5, проверка по исходным данным и итог — Claude Opus 5.5 (оба только с правом чтения); таблицы ниже посчитаны без модели.

## Сводка

### Главное

- **Обновление почти целиком серверное: Beastmaster.** API, строки и экспорт библиотек не менялись (api-changes.txt пуст; в so-diff у обеих .so «строки +0 −0, экспорт +0 −0»). Логика изменилась только у Beastmaster и у Hoodwink. Остальные изменённые функции — перекомпиляция.
- **Глобальные ауры талантов Beastmaster больше не исходят от иллюзий.** Речь о `special_bonus_unique_beastmaster_5` (+15 к скорости, KV `bonus_ms`) и `_6` (+250 здоровья, KV `bonus_hp`). Раньше `GetAuraRadius` всегда возвращал −1, то есть глобальный радиус. Теперь он возвращает 0, если у носителя стоит признак иллюзии. На клиенте проверка идёт через виртуальную IsIllusion, на сервере — через байт +0x16d2.
- **Ауры Beastmaster теперь определяют «своих» по ID игрока.** Раньше сравнивался указатель на контроллер игрока (слот 395), теперь ID игрока-владельца (слот 396). Это касается Inner Beast, Drums of Slom и обоих талантов: фильтра целей ауры, подсчёта юнитов для Inner Beast и выбора, кого лечит Drums of Slom.
- **Hoodwink: иллюзия Decoy создаётся с `permit_illusion_recycling = 0`.** Все остальные способности, которые ставят этот ключ, передают 1.
- **HUD-пинг руны, Death Prophet Exorcism, Ember Spirit Fire Remnant, Dawnbreaker Solar Guardian, курьер, бот фарма, регистрация `C_DOTA_Ability_Riki_Backstab`.** Здесь только перестановка блоков, другой инлайн и регистры. Логика по коду не изменилась.

### Новые свойства и методы: что делают

Новых свойств, событий, методов, флагов и поведений способностей в этой сборке нет.
- api-changes.txt пуст.
- В .so не добавлено ни одной строки (so-diff: «строки +0 −0»), ни одного экспорта, ни одной функции (func-diff: «добавлено 0, удалено 0»).
- Надёжность: высокая.

Единственное «новое имя» в коде — строка `permit_illusion_recycling` в Hoodwink Decoy. Но это не новое API: ключ таблицы параметров иллюзии был и в прошлой сборке, на него ссылались 16 мест, теперь 17. Он разобран в разделе «Изменения в коде игры».

### Для разработчиков кастомок

- **Lua API, Panorama, события, модификаторы, консольные переменные:** изменений нет (api-changes.txt пуст). Обычные аддоны это обновление сломать не должно.
- **Шум дампера, а не изменение игры** (dump-noise.md). Числовые значения части `ACT_*` различаются даже между двумя дампами одной сборки: `ACT_DOTA_CAST_FENCE`, `ACT_DOTA_CYCLONE`, `ACT_DOTA_RELAX_IN/OUT`, `ACT_DOTA_SPWN`, `muerta_debut_satyr_*`, `radiant_melee_mars_shieldbash` и др. Числа из дампа для этих активностей не хардкодьте, используйте имена.
- **Если в кастомке есть способности Beastmaster** (`beastmaster_inner_beast`, `beastmaster_drums_of_slom`, `special_bonus_unique_beastmaster_5/6`):
  - Принадлежность юнита Beastmaster'у теперь определяется по ID игрока-владельца, а не по указателю на контроллер игрока.
  - ID берётся так: у юнита с владельцем-героем — ID этого героя. Иначе, если у юнита выставлены флаги 0x20100, — поле +0x1014. В остальных случаях −1.
  - Возможное следствие, по коду не проверено: юниты без героя-владельца, которым ID игрока задан другим путём (например, через `SetControllableByPlayer`), теперь могут считаться «своими». Тогда они будут получать ауры, лечение Drums и входить в счётчик Inner Beast.
  - Таланты 5/6 больше не дают аур с иллюзий. Это касается и иллюзий, созданных через `CreateIllusions`.
- **Иллюзии:** `permit_illusion_recycling` — ключ в таблице параметров иллюзии, который движок читает при создании иллюзий. В документации API его нет (в files/ он не встречается). Что именно он делает и какое у него значение по умолчанию, по коду не установлено.

### Изменения в коде игры

**Beastmaster — таланты 5/6, `GetAuraRadius`** (server 0x44c8df0 / 0x44c8dd0, client 0x474b7e0 / 0x474b7b0)
- **Было:** `return -1` (глобальная аура).
- **Стало на сервере:** `GetParent()` (хэндл +0x74), затем `if byte[+0x16d2] != 0 → 0.0, иначе −1`.
- **Стало на клиенте:** `GetParent()->vfunc#451`, если true — 0.0.
- **Что такое слот 451 у героя** (`C_DOTA_BaseNPC_Hero`): возвращает true, если значение модификаторного свойства 170 равно 1, иначе байт +0xead. По enums.json 170 — это `MODIFIER_PROPERTY_IS_ILLUSION`, значит слот — IsIllusion().
- **Что такое +0x16d2 на сервере:** этот же байт проверяют вспомогательная функция «настоящий герой» 0x4360730 (флаг героя и `+0x16d2 == 0`) и функция учёта статистики 0x5088230.
- **Смысл:** глобальные ауры +скорость/+здоровье больше не исходят от иллюзий Beastmaster. По локализации они «глобальны, сохраняются после смерти и действуют на Beastmaster и всех его призванных».
- **Надёжность:** код — высокая. То, что флаг означает именно иллюзию, — средне-высокая: на клиенте это прямо IsIllusion, на сервере вывод по косвенным признакам.

**Beastmaster — `GetAuraEntityReject` четырёх аур** (Talent_5_Aura, Talent_6_Aura, DrumsOfSlom, InnerBeast_Aura; 0x44c95d0, 0x44c9630, 0x44c9690, 0x44c96f0)
- **Было:** `reject = caster->vfunc#395() != target->vfunc#395()` — сравнение 8-байтных указателей.
- **Стало:** `reject = caster->vfunc#396() != target->vfunc#396()` — сравнение int. Если кастера нет, цель по-прежнему отклоняется.
- **Что за слоты:**
  - 395 (`CDOTA_BaseNPC`/`_Hero::vfunc#395`) — `GetPlayerOwner`. Он разрешает хэндл владельца (+0x6bc), проходит по цепочке героев и возвращает сущность, если её vfunc +0x548 вернул true (по смыслу — контроллер игрока).
  - 396 — `GetPlayerOwnerID`. У героя это `return [+0x1dd8]`. У прочих NPC — ID владельца-героя, или поле +0x1014 при флагах 0x20100, иначе −1.
- **Смысл:** аура выбирает «юнитов того же игрока» по ID, а не по указателю на контроллер. Разница проявится там, где указатель и ID расходятся, например когда контроллера нет. Конкретный игровой сценарий по коду не установлен.
- **Надёжность:** код — высокая; трактовка слотов — средне-высокая.

**Beastmaster — `CDOTA_Modifier_Beastmaster_InnerBeast::OnIntervalThink`** (0x44f9a50)
- **Что делает:** обходит юнитов с `modifier_beastmaster_inner_beast_aura` и считает тех, у кого тот же владелец. Результат записывается в +0x1ab4.
- **Что поменялось:** то же 395→396, то есть сравнение указателей стало сравнением ID. Остальное — регистры и размер кадра стека.
- **Смысл:** по локализации грани Wild Hunt («бонус скорости атаки растёт с числом юнитов под Inner Beast») этот счётчик, вероятно, и задаёт бонус. Считаются юниты с тем же ID владельца.
- **Надёжность:** код — высокая; связь с гранью — средняя.

**Beastmaster — `CDOTA_Modifier_Beastmaster_DrumsOfSlom::OnIntervalThink`** (0x452ac80)
- **Что делает блок:** поиск юнитов в радиусе. Каждому NPC с тем же владельцем — лечение, частица `phoenix_sunray_beam_friend.vpcf` на `attach_hitloc` и всплывающее сообщение 0xa (`OVERHEAD_ALERT_HEAL`).
- **Что поменялось:** этот блок был и раньше — в диффе он удалён в одном месте и вставлен в другом. Изменилось только сравнение владельца: 395→396. Сообщение над головой по-прежнему адресуется через `GetPlayerOwner` (0xc58 остался).
- **Смысл:** Drums of Slom лечит «юнитов под его контролем» (так в локализации), определяя их по ID игрока.
- **Надёжность:** высокая.

**Hoodwink — `CDOTA_Ability_Hoodwink_Decoy::OnSpellStart`** (0x49404e0)
- **Что добавлено:** после `no_effect_on_original = 1` в таблицу параметров иллюзии пишется `permit_illusion_recycling = 0` — тот же сеттер 0x3a34290, `edx = 0`.
- **Как у других:** у прочих иллюзий — Phantom Lancer (Juxtapose, Doppelganger, Spirit Lance), Spectre Haunt и других — этот ключ равен 1.
- **Смысл по имени ключа:** иллюзию Decoy теперь, вероятно, нельзя «переиспользовать». Вероятно, это исправление бага, связанного с переиспользованием иллюзий.
- **Надёжность:** факт записи — высокая; смысл — средне-низкая.

**HUD: пинги на карте** (client 0x59f9e80; вызывается из `CHudDOTABase::vfunc#66`, `CDOTA_Hud_Minimap::vfunc#16`)
- **Что поменялось:** блоки переставлены. Отправка `dota_rune_spotted` (userid, rune, rune_team, map_location) осталась в функции: xref находит её в новой сборке по адресу 0x59fcac2.
- **Условие отправки:** если флаг установлен и с прошлого раза прошло больше 2 с (или разница времени отрицательна) — событие, иначе звук `General.PingRune`.
- **Единственная формальная разница:** при снятом флаге и отрицательной разнице времени старый код ещё мог отправить событие. Практически это невозможно.
- Ветки `General.PingAttack`/`General.PingDefense` только перенесены.
- **Надёжность:** высокая (старый и новый код сверены через disasm).

**Death Prophet — `Exorcism::OnIntervalThink`** (0x4554d00, +935 байт)
- **Что видно в коде:**
  - указатель на структуру духа переехал из r14 в r10, отсюда много сохранений в стек и восстановлений;
  - присваивание CHandle (константы 0x7fff, 0xf, поле +0x30) теперь встроено — поэтому прямых вызовов 181→180;
  - блок «перенести хэндл духа в список +0x1ae0 и удалить дух из +0x1af8» перенесён без изменений.
- Строки и константы данных не менялись. Это перекомпиляция.
- **Надёжность:** высокая.

**Ember Spirit — `Activate_FireRemnant::vfunc#371`** (0x492cd20)
- Обратный случай: встроенное присваивание хэндла +0x894 заменено вызовом функции (55→56 вызовов, исчезли 0x7fff, 0xf, +0x30). Плюс регистры и стек.
- Логика та же. **Надёжность:** высокая.

**Dawnbreaker — `Solar_Guardian_Thinker::OnIntervalThink`** (0x4939200)
- **Что поменялось:** ручная проверка «кастер — настоящий герой (флаг или vfunc#425) и не +0x16d2» заменена вызовом вспомогательной функции 0x4360730, которая делает ровно эту проверку. Её же вызывают ещё 99 функций (Rupture, Healing Ward и др.).
- Результат передаётся в функцию учёта статистики 0x5088230 (id 0x33e, принимает только настоящих героев), как и раньше. Остальное — inline-код расширения массива.
- Поведение эквивалентно. **Надёжность:** высокая.

**Riki — регистрация клиентского класса `C_DOTA_Ability_Riki_Backstab`** (client 0x47b30a0)
- Это статический инициализатор с вычислением ключа по MurmurHash2 (0x5bd1e995 и др. — константы MurmurHash, не криптография).
- Второй вызов хэш-функции заменён встроенными раундами с константами 0x3c798d9f и 0xde45aed5.
- Изменилось ли значение ключа и что это значит, неясно. На игровую логику Backstab это не указывает: серверный код Riki не менялся.

**Курьер — `CDOTA_Unit_Courier::Spawn`** (0x454af60)
- Вектор из одного значения 0x1c7c, который передаётся в vfunc +0xe8, теперь собирается из списка инициализации, а не через push.
- Перекомпиляция. **Надёжность:** высокая.

**Бот — `CDOTA_BotMode_Farm::vfunc#10` (GetDesire)** (0x5dfe860)
- Чтение `[r12+0xd8]` перенесено, но и в старом, и в новом коде сравнение идёт со значением после вызова.
- Эквивалентно. **Надёжность:** высокая.

### Бинарники

- **Изменились только `libclient.so` и `libserver.so`.**
- **libclient.so:** код +0 байт, изменено 4 функции.
- **libserver.so:** код +960 байт, изменено 14 функций.
- **Общее для обеих:** ни одной новой или удалённой строки, экспорта и функции. Число функций 280912 и 220000 не изменилось.
- **Что за этим стоит:** точечная правка одной фичи (Beastmaster: иллюзии и определение владельца) плюс исправление Hoodwink Decoy. Прочие отличия — побочный эффект перекомпиляции соседнего кода.
- Изменений движка, сети и систем, которые стояли бы за API, не видно. Изменений API в этой сборке нет.
