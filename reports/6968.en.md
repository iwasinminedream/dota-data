## Summary

### Highlights

- **No API changes.** The file `api-changes.txt` is empty: according to the dump, the Lua API, Panorama, events, modifiers and constants did not change. 11 `ACT_DOTA_*` constants, `muerta_debut_satyr_*` and `radiant_melee_mars_shieldbash` with different numbers are dumper noise (`dump-noise.md`), not a game change.
- **libclient.so did not change.** 0 functions changed out of 280912. In libserver.so 3 functions out of 220000 changed, none were added or removed. The strings and exports of both libraries did not change (`so-diff.txt`).
- **MegaMeepo (Meepo) fixed.** When `modifier_meepo_megameepo` is removed from a clone (the clone gets off the shoulders or is flung), the game now explicitly makes it visible again: it clears the EF_NODRAW flag. This is probably a fix for an invisible-clone bug. This is the only logic change in the build.
- **Legion Commander, Press The Attack: behavior did not change.** The code was recompiled: adding a target to the list was moved into a shared function. The constants and conditions are the same.
- **Muerta: not logic.** The code that registers the network variable `m_hDoubleShotTarget` changed: the compiler built the class name hash differently.

### For custom game developers

### Game code changes

**1. `CDOTA_Modifier_Meepo_MegaMeepo::OnDestroy`** (libserver.so, was 0x49e5640 → now 0x49e56a0, 703 → 743 bytes)

- **Whose modifier it is.** `modifier_meepo_megameepo`, carried by clones sitting on the main Meepo. This can be seen from the tooltip "The main hero can fling this clone" and from the KV `meepo_megameepo` / `meepo_megameepo_fling`.
  - `OnCreated` attaches the clone to the point `attach_megameepo_%d`.
  - `OnDestroy` detaches it (call `0x3b1b440(parent, 0, 0, 0)`), then knocks it back away from the main Meepo: `modifier_knockback` with `end_knockback_duration`, `end_knockback_distance`, `end_knockback_height`.
- **What was added.** Right after detaching, the following steps were added:
  - `parent = GetParent()`;
  - `parent->SetEffects(parent->m_fEffects & ~0x20)` — field +0x6c0, virtual slot 215 (+0x6b8);
  - call to `0x540dc30(parent)`.
  
  The rest of the code did not change.
- **Why this is "show the unit".**
  - Field +0x6c0 is `m_fEffects`: in the network schema the string `"m_fEffects"` is registered with offset `0x6c0` (xref at 0x3d726f8).
  - Bit 0x20 is `EF_NODRAW`: in the Lua API enumeration `EF_NODRAW = 32`.
  - Exactly the same sequence (`and 0xffffffdf` → `call [rax+0x6b8]` → `jmp 0x540dc30`) is found in `CDOTA_Modifier_Generic_Hidden::OnDestroy` and `CDOTA_Modifier_Phoenix_SupernovaHiding::OnDestroy`.
  - `0x540dc30` is called by 113 other functions, almost all of which return a unit to the world: Puck Phase Shift, Pudge Swallow, Riki Tricks of the Trade, Void Spirit Dissimilate, Monkey King, `CDOTA_BaseNPC::Spawn` and others.
- **What this means in the game.** A Meepo clone can no longer stay invisible (not rendered) after MegaMeepo. Who set EF_NODRAW on it, I did not find in the code: there is no such write in this modifier's `OnCreated` and `OnIntervalThink`. So this is more of a safeguard against a bug where the clone gets off "invisible" than a new mechanic.
- **Reliability.** That the code clears EF_NODRAW on the clone is established reliably. The reason for the change (which exact bug) is a guess. What `0x540dc30` does in essence is not established for certain: it is a general "after showing the unit" call.

**2. `CDOTA_Ability_Legion_Commander_PressTheAttack::OnSpellStart`** (was 0x4a7bdb0 → now 0x4a6daf0, 1618 → 1501 bytes)

- **What the function does.**
  - If `radius` > 0, it searches for units in the radius (`FindUnitsInRadius`, flag `0x13`).
  - It checks whether the target and Legion Commander herself are in the list, and adds the missing ones.
  - It applies `modifier_legion_commander_press_the_attack` to all units in the list (the constant `100` is the same), and launches the `..._aoe.vpcf` particle and the sound.
- **What changed.** Previously, adding to the `CUtlVector<EHANDLE>` was inlined in the function itself: `add r8d, 1`, `add eax, 1`, two `mov esi, 1` before expanding the array. Now a shared function `0x4a6b8b0` is called instead. It is also called by `Ogre_Magi_Smash::OnSpellStart`, `Ogre_Magi_Bloodlust::OnSpellStart`, `Medusa_MysticSnake` and Muerta code (DoubleShot). Hence the "−1 −1 −1 −1" in the summary: four ones left the function, they moved into `0x4a6b8b0`. The values and checks did not change, the rest is a change of registers and stack slots.
- **What this means in the game.** Nothing, the behavior is the same.
- **Reliability.** High.

**3. Unnamed function 0x4aa79f0 (Muerta, `m_hDoubleShotTarget`)** (was 0x4aa7a30, 3290 → 3322 bytes)

- **What it is.** It registers the network variable `CNetworkVarBase<CHandle<CBaseEntity>, CDOTA_Unit_Hero_Muerta::NetworkVar_m_hDoubleShotTarget>`; it has no callers. It is not game logic.
- **What changed.** Previously the tail of the class name `"CDOTA_Unit_Hero_Muerta"` (bytes 20–21, `"ta"`) was hashed by a function call (`lea rdi, [r13+0x14]; call`). Now this MurmurHash2 step is inlined directly into the code: `xor 0x6174` ("ta"), `imul 0x5bd1e995`, `shr 0xd`/`0xf`. The initial value `0x31415930` = `0x31415926 ^ 22` (the name length). The hash comes out the same.
- **What this means in the game.** Nothing, Muerta's Double Shot did not change.
- **Reliability.** High.

<details><summary>What Opus corrected in Haiku's draft</summary>

- **MegaMeepo.** Haiku said flag 0x20 is cleared "on the knockback modifier", and "+0x6c0" is a "new field". In reality EF_NODRAW is cleared in `m_fEffects` (the field is not new) on the clone itself, the carrier of the modifier, that is, the clone is made visible. The description of the in-game effect was rewritten and confirmed by comparison with Generic_Hidden and Phoenix SupernovaHiding.
- **Press The Attack.** Haiku said "four constants decreased by 1" and "target search logic reworked, conditions possibly changed". This is wrong: four ones were removed from the inlined vector addition, which is now called as a shared function. The logic did not change.
- **Muerta.** Haiku said "Double Shot validation changed, an integrity check or caching added". This is wrong: this is the registration of a network variable, where the compiler inlined the class name hash. The logic did not change.
- Haiku correctly identified the dumper noise (`ACT_*`). The conclusion "no new API" is confirmed: `api-changes.txt` is empty, there are no new strings or symbols.
