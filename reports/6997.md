# Dota 6997: что изменилось

Отчёт создан автоматически 2026-11-26. Черновик по всем изменениям (частей: 1) — Claude Sonnet 5.5, проверка по исходным данным и итог — Claude Sonnet 5.5 (только с правом чтения); таблицы ниже посчитаны без модели.

## Сводка

### Главное
- Технических изменений платформы нет. Клиент (`libclient.so`) не менялся: функции, строки и экспорт идентичны. В `libserver.so` функций 221948 → 221947, код стал меньше на 448 байт, строки и экспорт те же.
- Ограничений для кастомок, проверок режима игры (сравнение с 15), списков команд и конваров, браузерных проверок и новых отказов в этом обновлении нет.
- Единственное содержательное изменение сервера — защита от нулевого указателя в функции `0x5cb2bc0`. Она пишет отладочное сообщение и при пустом объекте подставляет строку `"none"`. На Lua API и поведение кастомок это не влияет.

### ⚠ Ограничения и странное
Не найдено.

### Новые свойства и методы: что делают
Новых нет.

### Для разработчиков кастомок
Изменений в Lua API, Panorama, событиях, перечислениях, консольных переменных и командах, KV-ключах нет. Существующие аддоны это обновление не ломает.

### Клиент (libclient.so)
Технических изменений клиента нет.

### Сервер и движок
- **`0x5cb2bc0`** (вызывается из `CDOTAPlayerController::vfunc#255` и ещё из `0x5ce0e10`).
  - Раньше при формировании отладочного сообщения читалось поле `[объект + 0x28]` без проверки.
  - Теперь код делает `test rax, rax` и при нуле берёт строку `"none"`.
  - Сообщение выводится только если проходит проверка `0x3b9f5e0(..., 2)`, похожая на проверку уровня логирования. Вызывается `0x3b9eae0` с форматной строкой.
  - Вывод: это защита логирования от краша, а не изменение логики. Надёжность высокая (код прочитан целиком), но смысл самого сообщения по коду не определён.
- **Остальные изменённые функции `libserver.so`** других технических изменений не содержат.

### Схема и протоколы
Изменений нет. Файлов, которые отслеживаются, в списке изменений нет.
