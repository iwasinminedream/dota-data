# Dota 6984: что изменилось

Отчёт создан автоматически 2026-11-19. Черновик по всем изменениям (частей: 4) — Claude Sonnet 5.5, проверка по исходным данным и итог — Claude Sonnet 5.5 (только с правом чтения); таблицы ниже посчитаны без модели.

## Сводка

### Главное

- **Сборка 6983 → 6984** (SourceRevision 11256873 → 11257680, 19 ноября 2026). Патч техничесий: нового контента (героев, предметов, ассетов) в данных нет. Основное изменение — в движке Lua-модификаторов.
- **Lua-модификаторы теперь получают 89 свойств и событий, которые движок раньше не вызывал.**
  - В `modifier_properties.json` у 89 записей флаг HasFunction изменился с `false` на `true`.
  - В libclient и libserver добавлено ровно по 89 обёрток по 36 байт. Каждая содержит имя Lua-колбэка (`GetModifierSpellRedirectTarget`, `OnTreePlanted` и т. д.) и вызывается из диспетчера Lua-модификатора.
  - Верхняя граница индекса свойства в диспетчере поднята с `0x191` (401) до `0x1a0` (416) = `MODIFIER_FUNCTION_LAST` − 1.
  - Раньше все свойства и события с id > 401 до Lua не доходили. Среди них `ON_TREE_PLANTED`=410, `ATTACK_POTENCY`=413, `HEALTHBAR_PIPS_FRAGILE`=416.
- **Исправлены опечатки в именах колбэков.**
  - Было `GetModifierPropetyFailAttack(event)`, стало `GetModifierPropertyFailAttack()`.
  - Было `GEtModifierSlowResistance_Unique`, стало `GetModifierSlowResistance_Unique`.
  - Для `INCOMING_DAMAGE_CONSTANT_POST` (303) вместо «описания = имя константы» появился метод `GetModifierIncomingDamageConstantPost`.
  - Для `INCOMING_DAMAGE_ILLUSION` (276) появился метод `GetModifierIncomingDamageIllusion`.
- **Sniper — Headshot.** Одиночный флаг «последний бросок удался» (`m_bLastRollSuccess`) заменён списком id записей атак `m_vecSuccessfulRolls`. Добавлено новое событие `ON_ATTACK_RECORD_DESTROY`, которое чистит этот список.
- **Enchantress — Impetus.** Смена анимации атаки (translate activity) стала условной. Для 5 активностей она применяется, только если Impetus реально сработает. На клиенте и на сервере добавлено событие `ON_ATTACK_FINISHED`.
- **Meepo — Fling Held.** Удерживаемый Meepo получает состояния `UNSELECTABLE` и `UNTARGETABLE`.
- **Meepo — Geomancy.** Поиск способности `meepo_divided_we_stand` перенесён из `OnCreated` в `OnIntervalThink`.
- **Прочее по коду.** Заметные изменения логики есть у Caduceus (последний аргумент вызова наложения модификатора 0→1), Mind Breaker и Chen (аура Zealot). Остальные расхождения в функциях — перекомпиляция или перенос кода между функциями.

**Нативные модификаторы (api-changes: +5)**

- **`modifier_enchantress_impetus` — `MODIFIER_PROPERTY_TRANSLATE_ACTIVITY_MODIFIERS`** (на клиенте формула появилась, на сервере изменилась; клиентская `vfunc#112` выросла с 86 до 519 байт, серверная `vfunc#128` — с 20 до 83 инструкций).
  - Обработчик отвечает на активности 1503, 1504, 1505, 1705 и 1758 (коды `0x5df…0x5e1`, `0x6a9`, `0x6de`, поле события `+0xc` = `activity`). Раньше он безусловно возвращал строку `"impetus"`.
  - Теперь `"impetus"` возвращается только если: у юнита нет `modifier_phantom_assassin_stiflingdagger_caster`; юнит не silenced; хватает маны (`GetEffectiveManaCost` не больше текущей маны); Impetus не на перезарядке; и либо способность именно сейчас кастуется, либо включён автокаст.
  - Основание: формула в `native_modifiers.json` и дизассемблер `0x47f80d0`. Надёжность высокая. Смысл: анимация атаки Impetus не включается, когда выстрела не будет.
- **`modifier_enchantress_impetus` — `MODIFIER_EVENT_ON_ATTACK_FINISHED`** (только сервер). В таблице свойств появилась запись `+0x11d0`, а новая функция `0x4805f50` её обслуживает. Она берёт атакующего, проверяет флаг живости (`+0xd3c & 1` и виртуальный слот `#427`) и вызывает функцию, содержащую строку `CNetworkTransmitComponent::StateChanged`. Вероятно, это пометка сетевого состояния для пересчёта анимации. Надёжность низкая: цель вызова не раскрыта.
- **`modifier_sniper_headshot` — `MODIFIER_EVENT_ON_ATTACK_RECORD_DESTROY`.** В таблице свойств появилась запись `+0x1250`. Обработчик — новая функция `0x4731710` (из `vfunc#97`):
  - берёт id записи атаки (`event+0x44`, 16 бит);
  - ищет его в массиве `+0x1b18` (по 2 байта на элемент);
  - если находит, подменяет последним элементом и уменьшает размер.
  
  Это очистка `m_vecSuccessfulRolls`, чтобы удавшиеся броски не копились. Надёжность высокая (код прочитан целиком).
- **`modifier_meepo_fling_held` — `MODIFIER_STATE_UNSELECTABLE` (14) и `MODIFIER_STATE_UNTARGETABLE` (37).**
  - `CheckState` на клиенте (`0x4b8df80`) и на сервере (`0x4b207f0`): маска «включить» `0x800022 → 0x2000804022`; маска «не трогать» `0xffffffffff7fffdd → 0xffffffdfff7fbfdd`. Добавлены биты 14 и 37.
  - Номера сверены с дампом (`MODIFIER_STATE_UNSELECTABLE`=14, `MODIFIER_STATE_UNTARGETABLE`=37).
  - Игровой смысл: Meepo, которого держат во Fling, нельзя выбрать и нельзя взять в цель. Надёжность высокая.

**Прочие новые имена из .so и схемы**

- **`CDOTA_Modifier_Sniper_Headshot::m_vecSuccessfulRolls`** (`CUtlVector<AttackRecord_t>`, `@6936`) заменяет `bool m_bLastRollSuccess`. Размер класса 6936 → 6960 (+24). Схема совпадает на клиенте и сервере. Логика Headshot по коду:
  - При успешном броске (функция `0x479a700`): `m_nRecord` (`+0x1b10`) записывается как раньше, а id записи добавляется в вектор вместо установки флага `+0x1b12`.
  - Бонус `modifier_sniper_take_aim_bonus` возвращает `headshot_chance` (`+0x1b0c`), только если id атаки есть в векторе.
  - В `0x4747820` (наложение `modifier_sniper_headshot_slow` и `modifier_sniper_headshot_knockback`) условие `record == [+0x1b10] && флаг != 0` заменено вызовом «найти и удалить id из вектора» (`0x4713460`, 128 байт). Эффекты накладываются, если id был в векторе.
  - Нативная формула `PROCATTACK_BONUS_DAMAGE_PHYSICAL` в `native_modifiers.json`: добавилась ветка «длина вектора ≤ 0 → 0, иначе %damage%».
  - Практически это значит, что Headshot теперь учитывает несколько одновременно летящих атак, а не одну последнюю. Это вывод из структуры кода; поведение в бою не проверялось.
- **Звук `Hero_ChaosKnight.ChaosStrike`.** В `0x4a6ede0` (вызывается из `ArcWarden_TempestDouble::vfunc#97`) строка `Hero_ChaosKnisght.ChaosStrike` заменена на `Hero_ChaosKnight.ChaosStrike`. Больше в функции ничего не менялось. Вероятно, звук крита Chaos Strike раньше не находился из-за опечатки. Существование soundevent в VPK не проверялось.

### Для разработчиков кастомок

- **Поведение существующих аддонов может измениться.**
  - Если ваш Lua-модификатор уже возвращал любое из 89 свойств или событий из `DeclareFunctions` (список выше), раньше оно молча игнорировалось. Теперь оно вызывается и применяется.
  - Проверьте модификаторы, написанные «впрок» или скопированные из других проектов.
  - Особенно проверьте те, что зависят от `FAIL_ATTACK`, `INCOMING_DAMAGE_CONSTANT_POST`, `PREREDUCE_INCOMING_DAMAGE_MULT`, `REPLACE_ATTACK`, `BECOME_*`, `FORCE_MAX_HEALTH` / `FORCE_MAX_MANA`, `ON_ORDER_RECEIVED`, `ON_MODIFIER_REMOVED`, `ON_TREE_PLANTED`.
- **Переименования.** Метод `GetModifierPropetyFailAttack` (с опечаткой) удалён из API. Используйте `GetModifierPropertyFailAttack`. Старое имя раньше и так не вызывалось (флаг был `false`), так что поломки нет, но и работать оно не начнёт. Аналогично `GEtModifierSlowResistance_Unique` → `GetModifierSlowResistance_Unique`.
- **Удалён «метод» `MODIFIER_PROPERTY_INCOMING_DAMAGE_CONSTANT_POST(event)`.** Это было описание константы, оформленное как метод, а не настоящий колбэк. Используйте `GetModifierIncomingDamageConstantPost`.
- **Enum `ACT_DOTA_LOADOUT_STATUE = 1801`** в строке api-changes — шум дампера. В контрольном дампе той же сборки `cl_script_reload` значение скачет 1801↔1807, а нумерация `ACT_DOTA_*` перетасовывается. Не считать это изменением; не хардкодьте числовые значения `ACT_DOTA_*`.
- **Шум дампера.** Предупреждение «LUA Memory usage warning…» и сдвиги `ACT_DOTA_*` (`CAST3_STATUE`, `CYCLONE`, `IMPALE`, `TORRENT`, `RELAX_IN/OUT`, `RUN_ALT`, `ACT_DOTA_SPWN`, пропажа `CAST5_STATUE` и др.) отражают нестабильность дампера, а не игру.
- **Нативные модификаторы (65 «~» в api-changes): почти все — замена литералов флагов на имена констант** в декомпиляции формул. Логика не меняется. Примеры: `damage_flags & 32` → `DOTA_DAMAGE_FLAG_HPLOSS`, `& 16` → `DOTA_DAMAGE_FLAG_REFLECTION`, `& 1024` → `DOTA_DAMAGE_FLAG_NO_SPELL_AMPLIFICATION`, `& 4` → `BYPASSES_INVULNERABILITY`, `& 131072` → `MAGIC_AUTO_ATTACK`, `& 48` → `REFLECTION | HPLOSS`, `damage_category & 1` → `DOTA_DAMAGE_CATEGORY_ATTACK`, `damage_type ~= 1/2` → `DAMAGE_TYPE_PHYSICAL/MAGICAL`.
  - Затронуты щиты, барьеры и проценты урона: Abaddon Aphotic Shield, Bristleback, Centaur Stampede, Crystal Maiden Frostbite, Doom, Lich Frost Shield, Nyx Burrow/Spiked Carapace, Ursa Enrage, Wisp Tether, Zeus Thunder Trail, Bloodstone, Veil of Discord, Gale Guard, Martyr's Plate, Faceless Void Backtrack, Juggernaut Duelist, Kez Parry, Spectre Dispersion, Treant Living Armor, Tinker Defense Matrix и др.
  - Для `modifier_item_invisibility_edge_windwalk` (клиент) изменился только адрес в формуле (`6539194776` → `6539202968`) — это перекомпиляция.
  - `modifier_sniper_keen_scope` (клиент) изменился в хвосте выражения, видимой логики не меняет.
  - Реальные поведенческие изменения среди «~»: Impetus и Sniper Headshot (описаны выше).
- **Panorama, консольные переменные, события игры, API KV (`abilities.json`, `units.json`):** по данным изменений нет.
- **Dispatcher Lua-модификатора на клиенте и сервере** (`CDOTA_Modifier_Lua::vfunc#88` и `vfunc#97`) обслуживает теперь индексы до 416. Для кастомок это значит, что все `MODIFIER_PROPERTY_*` и `MODIFIER_EVENT_*` до `MODIFIER_FUNCTION_LAST` (417) получили путь вызова в Lua.

### Изменения в коде игры

Всего: libclient — изменено 61, добавлено 93, удалено 4, копий существующего кода 12. libserver — изменено 147, добавлено 102, удалено 6, копий 18. Полный список: `so-query funcs libclient.so` / `libserver.so` (в репозитории отчётов — `reports/6984-functions.md`, если он есть).
