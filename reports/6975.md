# Dota 6975: что изменилось

Отчёт создан автоматически 2026-11-13. Черновик по всем изменениям (1 частей) — Claude Haiku 4.5, проверка по исходным данным и итог — Claude Opus 5.5 (оба только с правом чтения); таблицы ниже посчитаны без модели.

## Сводка

### Главное

- **Новая категория жалобы на игрока — «Бот» (Botting).** Добавлены две строки локализации: `DOTA_PlayerReportPopup_Botting_Title` («Botting», в русской локализации «Бот») и `DOTA_PlayerReportPopup_Botting_Tooltip` («Their hero is being played by automated software instead of a person.», по-русски «Этим героем управляет автоматизированная программа, а не человек.»). В libclient.so появились строки `BottingButton` и `#DOTA_PlayerReportPopup_Botting_Title`.
- **Окно жалобы `CDOTA_DB_Popup_ReportPlayerNew` получило седьмую кнопку отрицательной категории.** Раньше их было шесть: ToxicText, ToxicVoice, EnemySmurfing, Griefing, EnemyCheating, DidNotPlayRole. Объект окна вырос с 0xf0 до 0xf8 байт, и общий цикл обновления кнопок категорий теперь обходит 7 кнопок, а не 6.
- **Причину «Botting» теперь можно показать в списке успешных жалоб.** Функция «номер причины → заголовок» получила новую ветку. Число причин (0…13) не изменилось: значение, видимо, уже было в перечислении, но заголовка у него не было.
- **Игровая логика не менялась.** В libserver.so изменено 0 функций, 0 строк и 0 экспортов. Lua API, Panorama API, события и модификаторы тоже не менялись: в api-changes.txt только две строки локализации.
- Остальные изменения libclient.so — перекомпиляция: сдвиг таблиц переходов, другое решение компилятора о встраивании кода и склейка двух функций анализатором.

### Новые свойства и методы: что делают

Новых свойств, событий и методов Lua API или Panorama в этой сборке нет. В api-changes.txt только локализация, проверять HasFunction не для чего.

- `BottingButton` — это не API. Это идентификатор панели в макете Valve `file://{resources}/layout/popups/popup_report_player_new.xml`. Конструктор окна жалобы (0x681a480) ищет её по имени, проверяет тип и сохраняет указатель в новое поле объекта +0xf0. Основание: строка рядом с другими кнопками категорий (so-query context) и код конструктора (fdiff). Надёжность высокая. Для кастомок значения не имеет.
- В черновике Haiku в «API» записаны «методы» vfunc#51/#9/#61/#58. Это не новые методы, а виртуальные вызовы движка Panorama: поиск дочерней панели по имени и проверка её типа. Конструктор просто повторяет их для новой кнопки. В API ничего не добавилось.

### Для разработчиков кастомок

- Изменений Lua API (vscripts), Panorama API, игровых событий, модификаторов и консольных переменных нет. Существующим аддонам ничего не грозит.
- Новые ключи локализации `DOTA_PlayerReportPopup_Botting_Title` и `DOTA_PlayerReportPopup_Botting_Tooltip` есть во всех языках (проверено, например, в russian, ukrainian, latam, turkish). Это интерфейс основной игры, к кастомкам он не относится.
- Числа динамических активностей в `cl_script_reload` (`ACT_DOTA_CAST5_STATUE`, `ACT_DOTA_VOODOO_REST`, `ACT_DOTA_CYCLONE`, `ACT_DOTA_TORRENT`, `muerta_debut_satyr_*` и др.) различаются даже между двумя дампами одной сборки (dump-noise.md). Например, `ACT_DOTA_CAST5_STATUE` было 1801 в прошлом дампе и стало 1804 в текущем. Это не изменение игры, но вывод из него такой: числовые значения этих ACT_* нельзя зашивать в код, обращайтесь к ним по имени.

### Изменения в коде игры

Всего изменено 19 функций, все в libclient.so; в libserver.so изменений нет.

**Окно жалобы на игрока (8 функций)**

- **0x681a480 — конструктор `CDOTA_DB_Popup_ReportPlayerNew`.** Его вызывают сразу после `operator new(0xf8)`: в 0x71c3640 (с табло, `dota_hud_scoreboard_player.xml`) и в 0x6570340.
  - После сохранения последней старой кнопки в `[this+0xe8]` добавлен поиск панели `"BottingButton"`, проверка её типа и запись в `[this+0xf0]`.
  - Также добавлены три ветки сообщения об ошибке приведения: `"Attempted to cast panel '%s' to type '%s'"`, `"!pPanel || pResult"`, константа 0x5b2 — вероятно, номер строки в исходнике. Это служебный код проверки, встроенный вместе с поиском панели.
  - Новых условий для других категорий нет.
  - Основание: fdiff целиком, context. Надёжность высокая.
- **Размер объекта окна 0xf0 → 0xf8.** Так меняются четыре функции:
  - 0x71c3640 (`"OverwatchReport"`; вызывается из строки игрока на табло) — `operator new(0xf8)` и затем конструктор;
  - 0x6570340 — `operator new(0xf8)`; её вызывает страница итогов матча (`dashboard_page_post_game_overview_*`), то есть жалобу открывают и после игры;
  - 0x6807b30 `CDOTA_DB_Popup_ReportPlayerNew::vfunc#63` — деструктор: вызов деструктора базового `CUI_Popup` и освобождение 0xf8 байт;
  - 0x6807c90 — тот же размер при освобождении.

  Это не «смещение поля» и не «8-байтная структура хранилища», как писал Haiku: появился один новый указатель на панель. Надёжность высокая.
- **0x6837d70 `CDOTA_DB_Popup_ReportPlayerNew::vfunc#57` — обработка выбора категории** (`"Report_AnyCategorySelected"`, `"reason"`, `"OverwatchApplicableReport"`).
  - Цикл по кнопкам категорий `[this+0xc0 … +0xf0)` теперь идёт до `+0xf8`, то есть кнопка Botting получает то же обновление `reason`, что и остальные.
  - Проверка «жалоба подходит для Overwatch» не изменилась: среди выбранных категорий ищется тип 5 или 6 (`sub edx,5; cmp dl,1`).
  - Флаг перенесён из регистра r15 в стековую переменную — это перераспределение регистров, не новый флаг.
  - Входит ли Botting в категории для Overwatch, по этому коду не определить: типы категорий берутся из данных, заполняемых в другом месте.
  - Надёжность высокая для расширения цикла, для Overwatch вывод неясен.
- **0x5bc7940 — функция «номер причины → `#DOTA_PlayerReportPopup_*_Title`».** Её вызывает 0x67e5710 (`"SuccessfulReportSnippet"`, `"successful_report_reason"`, `"NoSuccessfulReports"`) — список успешных жалоб.
  - Граница `cmp edi, 0xd` осталась прежней; добавлена ветка `#DOTA_PlayerReportPopup_Botting_Title`. Значит, один номер причины, который раньше давал значение по умолчанию, теперь получает заголовок «Botting».
  - Перестановка `GoodTeamwork`/`ToxicVoice` в диффе — это другое расположение веток в коде, а не новый порядок категорий (у Haiku ошибка).
  - Надёжность высокая для новой ветки. Сам номер причины не установлен.
- **0x682eb70 — окно голосования за короткометражки (`popup_short_film_workshop_vote.xml`).** Поиск и проверка одной из панелей (перед `NextButton`) раньше была встроена в функцию, теперь это вызов общей функции 0x6806010. Поэтому «пропали» строки ошибки приведения и виртуальные вызовы. Поведение то же, это решение компилятора. Код не «переехал» в окно жалобы, как предполагал Haiku. Надёжность высокая.

**Перекомпиляция, не логика (11 функций)**

- **Сдвиг таблиц переходов `switch` в .rodata на 0x100 байт (10 функций):** 0x3ab8100 (поля `m_CoverImage`, `m_URLForImages`…), 0x3afbfb0 `C_DynamicPropClientFadeOut::vfunc#10`, 0x3afc8a0, 0x3b3c0d0 `CPointClientUIWorldTextPanelPreviewer::vfunc#2`, 0x3b4cc90, 0x3b4f100, 0x3b4f340, 0x3b4f580, 0x3b8edb0 `CNetworkTransmitComponent::vfunc#3`, 0x3bd0e00.
  - Во всех изменился только адрес таблицы после `cmp …, 6; ja`. Анализатор показывает её как «строки» вида `"uQl"→"uRl"`, `"1ip"→"1jp"`. Число инструкций не изменилось.
  - Это следствие двух новых строк в .rodata. Надёжность высокая.
- **0x5bca8d0 — склейка функций анализатором.**
  - Новые «35 строк в начале» — это получатель статического объекта, создаваемого при первом обращении (проверка флага, `__cxa_guard_acquire`, конструктор 0x5bca7a0, `__cxa_atexit`, `__cxa_guard_release`).
  - В старой сборке он был отдельной функцией 0x5bca7b0 с заполнением `int3` после неё. В новой следующая функция начинается сразу за `ret` (0x5bca940), и анализатор слил их. Отсюда «функций 280912 → 280911» и «одной копией меньше: 0x5bca7b0».
  - Логика не изменилась (disasm old/new). Надёжность высокая.
