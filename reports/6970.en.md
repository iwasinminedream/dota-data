# Dota 6970: What Changed

The report was generated automatically on 2026-11-16. The draft of all changes (parts: 1) was written by Claude Sonnet 5.5; the verification against the source data and the final version were done by Claude Sonnet 5.5 (read-only access); the tables below were calculated without a model.

## Summary

### Highlights
- Version 6970 (build 26395008, 02.11.2026) has no changes to game logic, balance, Lua API, Panorama, events, or console variables.
- Exactly two client native modifier functions changed. In both, a single numeric constant differs: `6537541320` → `6537545416`. The difference is 4096 (0x1000).
  - `modifier_item_invisibility_edge_windwalk`, property `PREATTACK_BONUS_DAMAGE_POST_CRIT`.
  - `modifier_sniper_keen_scope`, property `PROCATTACK_BONUS_DAMAGE_PHYSICAL`.
- This looks like an absolute address shift caused by rebuilding the client library. Both constants are part of the same expression with `params.record`: `((record & 1023) + (record & 1023) * 8 << 5) + <constant>`. The expression looks like address arithmetic over the attack record, and the constant looks like the base address of a table. The base address in the same expression shifted by the same amount in two different modifiers. This is a sign of recompilation, not a logic change. Confidence: high that the formula values did not change. I did not check what exactly the address behind the constant points to: there are no .so sources or func-diff in this version.
- The `cl_script_reload` section (renumbering of `ACT_DOTA_*`, the new `ACT_DOTA_SPWN`, the vanished `ACT_DOTA_CAST5_STATUE`) is dumper noise, which is confirmed by the control dump `dump-noise.md` of the same build. It is not counted as a game change.

### New properties and methods: what they do
There are no new properties, events, or methods. Additions and removals in the API are zero (`+0 −0`), there are only two changed values. The `HasFunction` test and xref over the .so are not needed here: the property names are not new.

### For custom game developers
- Nothing breaks. Names, signatures, and behavior did not change. Both affected properties already existed.
- What these expressions do (from the dump, confidence high):
  - `modifier_item_invisibility_edge_windwalk` (Silver Edge / Invisibility Edge). The client version of `PREATTACK_BONUS_DAMAGE_POST_CRIT` returns `%windwalk_bonus_damage%`. For buildings and targets where `IsOther()` is true it returns 0. Next come checks of the attack record `params.record`: `record & 64512 ~= 0` and `& 2`.
  - `modifier_sniper_keen_scope` (Sniper's Take Aim, i.e. Keen Scope). The client version of `PROCATTACK_BONUS_DAMAGE_PHYSICAL` is calculated as follows:
    - If the attacker is not the owner of the modifier, the result is 0.
    - If the `caster` has `MODIFIER_STATE_PASSIVES_DISABLED`, the result is 0.
    - If the target is on the same team or is a building, the result is 0.
    - In all other cases it is `%bonus_damage_for_range% * (distance / %bonus_damage_distance%) / 100 * ?`. The distance is calculated in the plane (sqrt(dx²+dy²)).
  - The formulas are the same as in the previous version (6969). Comparison with `changelog-states/6969.json` showed that only the constant changed.
- If client-side prediction depends on these formulas, the behavior will not be affected.
