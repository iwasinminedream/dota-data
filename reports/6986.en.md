# Dota 6986: what changed

The report was generated automatically on 2026-11-20. The draft covering all changes (parts: 3) was written by Claude Sonnet 5.5, and the check against the source data and the final version were done by Claude Sonnet 5.5 (read-only access); the tables below were calculated without a model.

## Summary

### Highlights

- **Morphling, Replicate (Aghanim's Scepter upgrade), echo:** the main content of build 6986. The echo has been taught to copy **Tusk Snowball**. The original finishes its windup, and only then do the echoes appear, while their own windup is reset to zero. Evidence: new schema fields `m_hPendingSnowball*`, functions in `libserver.so` and native echo properties (details in the next section).
- **Morphling, echo:** several other rules were rewritten.
  - A blacklist of abilities that the echo does not repeat has appeared: 17 names, but the names themselves could not be extracted from `.so`.
  - The echo does not disappear while it is moving (`modifier_hoodwink_arcing_boomerang`, `modifier_marci_lunge_*`, `modifier_death_seeker_out_of_world`, `modifier_tusk_snowball_movement`) or while `modifier_grimstroke_spirit_walk_buff` is active on the target.
  - A new virtual method of abilities (slot 241) copies the ability's state into the echo's copy.
  - `MODIFIER_PROPERTY_STATUS_RESISTANCE_CASTER` is now equal to `100 - echo_power`, whereas it was `echo_power - 100`. This agrees with the tooltip: each subsequent echo should apply shorter buffs and debuffs.
- **Shadow Shaman, Shackles:** the search for `modifier_shadow_shaman_shackles` now uses a "caster + ability" filter. Previously there was no filter. The change is in `OnChannelThink`, `OnChannelFinish` and in a new helper function extracted from the old block.
- **Rubick, Spell Steal:** `Beastmaster_SummonThunderhide` and `Chen_Zealot` now have their own `OnUnStolen`. Judging by the code, when the stolen ability is lost they remove or kill the units it created (conclusion of moderate reliability).
- **Nature's Prophet, Nature's Call (`furion_force_of_nature`):** the client's own `CastFilterResultLocation` check has been removed. It counted trees in `area_of_effect` and otherwise returned an error. Now only the general point validity check remains. The server-side ability code was not changed.
- **Ogre Magi, Bloodlust:** the attack speed substitution on `self_bonus` for the caster has been moved from `OnCreated`/`OnRefresh` into the property getter. The resulting value is the same.
- **Everything else:** text updates (80 localization files in the VPK) and a large amount of recompilation "noise". In the schema classes, only two Morphling modifiers changed. There are no new events, enums or API constants.

### New properties and methods: what they do

All three entries from `api-changes.txt` belong to `modifier_morphling_replicate_echo`. The constants themselves are not new: they were already in `enums.json` and `modifier_properties.json` (`HasFunction = true`) and are mentioned in `previous-dump.txt`. What is new is that this built-in modifier implements them. The rest below are new methods and fields found in the code.

**`MODIFIER_PROPERTY_OVERRIDE_ABILITY_SPECIAL`** (`GetModifierOverrideAbilitySpecial`, server)
- **What it does:** returns 1 ("I override this value") only if the ability is named `tusk_snowball` and the requested special is `snowball_windup`. Otherwise it returns 0.
- **Evidence:** the dump and the disassembly of `0x44a4140`. It compares `[ability+0x840]` with the string `tusk_snowball`, and the special name in the event (`ability_special_value`) with the string `snowball_windup`. The dump's "formula" in `api-changes.txt` with `? == 0 ? 1 : 0` is decompilation garbage.
- **How to use it:** in a Lua modifier, implement the pair `GetModifierOverrideAbilitySpecial(event)` and `GetModifierOverrideAbilitySpecialValue(event)`. Event fields: `ability`, `ability_special_value`, `ability_special_level`. The first function says that the special is overridden, the second returns the number.
- **Reliability:** high for the function itself, medium for the interpretation. The purpose is inferred from the combination with the rest of the code.

**`MODIFIER_PROPERTY_OVERRIDE_ABILITY_SPECIAL_VALUE`**
- **What it does:** a constant 0 (dump).
- **Conclusion:** together with the previous item, `snowball_windup` for the copy of `tusk_snowball` in the echo equals 0. The echo snowball starts without a windup (in KV `snowball_windup` = 3). In parallel, the original Tusk waits for the normal windup.
- **Reliability:** medium.

**`MODIFIER_EVENT_ON_MODIFIER_REFRESHED`** (`OnModifierRefreshed`, server)
- **What it does:** a new handler for `0x44be040`. Its details below are given with low reliability; the gist is given by the code logic.
  - Reacts to the update of another's modifier if the target is the echo's `m_hDebuffTarget`.
  - Compares the modifier's ability name with the echo's ability (`<NoAbilityName>` if absent).
  - Looks it up in the table of entries by `[modifier+0x50]` and, for the entry found, calls `SetDuration(...)` with the saved duration.
- **The table is written by** `GetModifierStatusResistanceCaster` (`0x44a83a0`). It takes a snapshot of the target's modifiers (id, duration, remaining time) into a vector by `+0x1b18`, and returns `100 - echo_power` (`+0x1b30`).
- **Conclusion:** the echo should not shorten or extend debuffs already on the target with its weakened application. This is a hypothesis.
- **Reliability:** low.

**`MODIFIER_PROPERTY_STATUS_RESISTANCE_CASTER`** (changed)
- **What changed:** the formula was `echo_power - 100`, now it is `100 - echo_power`. Confirmed by the dump and the code of `0x44a83a0`: `100.0 - [+0x1b30]`.
- **Meaning:** a positive value shortens the duration of the effects applied by the echo. It matches the localization of `scepter_description` ("applying shorter buffs/debuffs").
- **Reliability:** high.

**New schema fields** (`SchemaSystem`, offsets confirmed by the code)
- `CDOTA_Modifier_Morphling_Replicate_Echo.m_hDebuffTarget` (`CHandle<CBaseEntity>`, @6932 = `0x1b14`). Read in `OnModifierRefreshed`.
- `CDOTA_Modifier_Morphling_Replicate_Echo_Source`:
  - `m_hPendingSnowball` (@6904 = `0x1af8`);
  - `m_hPendingSnowballTarget` (@6908 = `0x1afc`);
  - `m_flPendingSnowballWindupEnd` (`GameTime_t`, @6912 = `0x1b00`).
- Reliability is high: the schema, the names in `.so` and the accesses in `0x4513610` / `0x4513820` match.

**Deferred echo snowball logic** (`Echo_Source`)
- **`0x4513610`** is the body of the `Echo_Source::vfunc#97` handler (in native modifiers this is `OnAbilityFullyCast`). If `tusk_snowball` is applied, it stores the ability and the target in `m_hPendingSnowball*`. The windup end time is computed as `GameRules time + GetSpecialValueFor("snowball_windup")`. `StartIntervalThink(0)` is enabled. Otherwise the echo creation `0x4512ee0` is called immediately.
- **`Echo_Source::OnIntervalThink`** (`0x4513820`, new): waits while Morphling has `modifier_tusk_snowball_movement`. If the ability `tusk_launch_snowball` is absent, its flag `[+0x7a6]` equals 0, or the time is ≥ `m_flPendingSnowballWindupEnd`, it creates the echo via `0x4512ee0`. Then it resets the handle and calls `StartIntervalThink(-1)`. If the movement modifier has disappeared, the state is simply cleared.
- Reliability is moderate: the meaning of the flag `+0x7a6` is undetermined.

**Abilities: slot `vfunc#241`** (a new virtual method "copy the ability's state into the copy for the echo", moderate reliability)
- Implementations: `Bane_Nightmare`, `Muerta_DeadShot` (was 81 bytes, now 305), `Tusk_WalrusKick` (369 bytes), `Marci_Companion_Run` (32 bytes).
- `Tusk_WalrusKick` (analyzed in detail): the arguments are the original, the copy, and one more parameter. If the owner has the ability `morphling_replicate`, the vector +0x860/+0x868 (the received target/direction vector) is copied. Otherwise the vector is recomputed relative to another unit's position.
- `Marci_Companion_Run` simply copies the field `+0x884/+0x88c`. Reliability is moderate.

**Abilities: slot `vfunc#239`**
- `Marci_Companion_Run::vfunc#239` used to always return 0, now it returns the byte `+0x858` of the ability.
- This byte is set to 1 by `0x44df160` (`Echo`) for the duration of the copy's cast call and reset to 0 afterwards. It is a marker of "the ability is currently being cast by an echo".
- Reliability is medium: whether the slot is named this way in the engine is unknown.

**Other new functions:**
- `CDOTA_Ability_Beastmaster_SummonThunderhide::OnUnStolen` (`0x4667890`) and `CDOTA_Ability_Chen_Zealot::OnUnStolen` (`0x482dbf0`):
  - Both, after the base `OnUnStolen`, take the saved handles, check that the unit is alive, and call `0x61b8120`.
  - The same function is called by `OnDestroy` of `Juggernaut_Healing_Ward_Aura`, `Lich_Ice_Spire` and `Morphling_Replicate_Echo::OnDestroy`. So this is more likely removing or killing a unit, but the exact name is unknown.
- New identifiers in `libserver.so` (`strings +4`): `m_flPendingSnowballWindupEnd`, `m_hDebuffTarget`, `m_hPendingSnowball`, `m_hPendingSnowballTarget`. These are schema fields, not API.

### For custom game developers

- **Lua API and Panorama:** no changes. There are no new functions, events or constants either. There are no removals or renamings either. `OVERRIDE_ABILITY_SPECIAL`, `…_VALUE` and `ON_MODIFIER_REFRESHED` existed before, and this build only added their implementation in the built-in `modifier_morphling_replicate_echo`. If your addon uses this pair for Tusk Snowball, the behavior will be the same as for the echo. Limitation: `HasFunction` for these properties is equal to `true` — the engine calls them on Lua modifiers.
- **What may break existing addons:**
  - Custom games with Morphling that have Scepter and Replicate:
    - the echo now does not copy abilities from the blacklist (the list was not extracted);
    - the echo is not removed while the Morphling illusion is moving;
    - the duration of the echo's buffs and debuffs has become shorter (sign `STATUS_RESISTANCE_CASTER`);
    - the echo's behavior with Tusk Snowball has changed noticeably.
  - Custom games with Shadow Shaman: Shackles now counts and removes only its own modifiers, not any with that name. If you have several Shackles on one target (for example, two heroes or Rubick), the behavior will change.
  - Custom games with Rubick and stolen `beastmaster_summon_thunderhide` / `chen_zealot`: when the ability is lost, cleanup now triggers (according to the code); previously there was none.
  - Custom games with Nature's Call: the client-side check for trees in the area has been removed. The server still limits the number of treants to the number of trees, as stated in the localization.
- **Console variables, network event schema:** none new.
- **Dumper noise** (`cl_script_reload`, `ACT_DOTA_*`, `muerta_debut_satyr_*`): classified as unstable; per `dump-noise.md` these are not game changes.

### Game code changes

In total for `libserver.so`: 334 functions changed, 20 added, 6 removed, 17 "code copies". For `libclient.so`: 6 / 1 / 2 and 7 copies. For `libtier0.so`: 3 changed. Full list: `reports/6986-functions.md` and `so-query.py funcs`.

**Morphling Replicate (detailed, server)**
- `Replicate_Echo::OnIntervalThink` (`0x44df4d0`, 198 → 700 bytes; ≈ "first tick").
  - The first tick now computes the lifetime as `now + scepter_echo_visible_duration` (the field became `+0x1b34`) and calls `0x44df160` (echo cast).
  - Then, if the echo (parent) does not have `modifier_item_lotus_orb_channel_check`, a busy check is performed: whether there is `modifier_tusk_snowball_movement`, `modifier_death_seeker_out_of_world`, `modifier_hoodwink_arcing_boomerang`, `modifier_marci_lunge_tracking_motion`, `modifier_marci_lunge_arc`, as well as `modifier_grimstroke_spirit_walk_buff` on the target (`echo_target`).
  - If any of these is present, the lifetime is shifted again: `0.5 + visible_duration`. Through the virtual calls `+0x1f8` and `+0x2f8` (GetRemainingTime/SetDuration — presumably) the modifier itself and `modifier_illusion` are extended.
  - Otherwise, when the time runs out, removal is called (`0x5057660`, as in the old code).
  - Reliability is high for the structure, medium for the names of the virtual calls.
- `0x44df160` — the line that calls the echo cast. `byte [ability+0x858] = 1` was added before the cast and `= 0` after it. Reliability is high.
- `0x44dee60` (inside the `0x44ddd80` block, 4483 → 4662 bytes): a filter "can the echo repeat this ability".
  - Not passive, behavior with the `8` bit (presumably UNIT_TARGET), the `+0x54` field of the type is not equal to 1.
  - New: the ability name is compared against a table of 17 names (8 bytes per pointer via `0x7f1c340`); on a match it cannot be repeated. Previously the function simply returned `state != 1`.
  - The list of names from `.so` cannot be extracted without the relocation data. Reliability is high for the structure; the names are unavailable.
- `Echo_Source` echo creation (`0x4512ee0`, 1677 → 1839 bytes): the handle checks were moved into the calling code. Added: after the illusion is created, `ogre_magi_multicast` is looked up, and if it exists, a virtual method in slot 245 is called with argument 0. Most likely, Multicast is disabled or reset for the echo. This is a hypothesis.
- `Echo_Source::vfunc#97` and `OnIntervalThink` — see the section on the delayed snowball above.
- Classes: `Echo` grew by 24 bytes, `Echo_Source` by 16. In the constructors and `CModifierFactory<…>::vfunc#0` there are new sizes of `0x1b38` and others. `Echo` contains a vector at `+0x1b18/+0x1b20/+0x1b28` (elements of 12 bytes) that is not in the schema.
- `Replicate_Echo::vfunc#97` (`0x445a320`) — just a property registration table: three new slots were added (`OVERRIDE_ABILITY_SPECIAL` and others). Three small getters read `echo_power` at the new offset `0x1b30`.
- Glue and copies: `0x4492c30`, `0x44930e0`, `0x4485390`, `0x447d460` (removed, replaced by three new functions).

**Shadow Shaman, Shackles (server)**
- `OnChannelThink`, `OnChannelFinish`, new `0x45e1810` (860 bytes, called from `OnSpellStart`): the modifier lookup is now `FindModifierByNameAndCaster(target, "modifier_shadow_shaman_shackles", GetCaster(), ability)` instead of `(…, 0, 0)`. This applies to the check, the removal, and the calculation of the maximum remaining duration.
- `0x45e0dd0` (1609 → 784 bytes): the block "maximum remaining duration along the chain; write to the networked field `+0x85c`" was extracted from it and became a standalone function `0x45e1810`. It did not lose any logic of its own.
- Reliability: high for the calls themselves; the gameplay effect is inferred from the names.

**Nature's Prophet (client)**
- Removed `C_DOTA_Ability_Furion_ForceOfNature::CastFilterResultLocation` (`0x4a1efd0`). It counted entities (trees) in `area_of_effect` via `0x4a1ec40`, returned code 23 if there were none, and otherwise passed control to the common check. Now the slot points to the common `0x4f7cc30` (rejection only if the coordinates are equal to `FLT_MAX`, code 24). There are no server changes.

**Ogre Magi, Bloodlust** (client `0x4bee4d0`, server `0x4bf1260`)
- The `if (GetCaster() == GetParent()) [0x1af8] = [0x1b00]` branch was removed from `OnCreated`/`OnRefresh`. Getters appeared (`0x4b36490` on the server, `0x4b95910` on the client): if `GetCaster() != GetParent()`, `bonus_attack_speed` (`+0x1af8`) is returned, otherwise `self_bonus` (`+0x1b00`). In the KV `self_bonus` for Ogre Magi — `40 60 80 100`.
- The resulting value is the same, but it is computed on the fly rather than on creation and update.
- Reliability: high. Which property exactly the getter returns (`vfunc#97` on the server, `vfunc#88` on the client) was not verified.

**Huskar, Berserker's Blood** (client `0x49f47a0`, 680 → 803 bytes)
- This is not a new formula. Previously a separate function (`0x4a14b90`) already computed `((clamp((v-lo)/(hi-lo),0,1)·100)^1.85) / 100^1.85` via `V_powf`. Now it is inlined into the body. The constants 100, 1 and 1.85 were in the old function. The logic did not change. Reliability is high.

**Venomancer, Noxious Plague** (`0x4773f80`)
- Before applying `modifier_venomancer_noxious_plague_contagious`, a check of the virtual method `vfunc#167` (`+0x538`) of the target was added; with `false` the infection is skipped. Plus a small new path with `r15-1`.
- What exactly slot 167 checks has not been established; judging by other places (`Echo` cast, `OnUnStolen`) it is a boolean "unit is valid" check (presumably alive). Reliability is low.

- **Ogre Magi Bloodlust:** the draft claimed that the bonus is no longer substituted on the caster itself. The substitution did not disappear, it was moved into the property getter (server-side `0x4b36490`, client-side `0x4b95910`).

- **Hero death `vfunc#129`:** this is not a "read of the field `+0x538`", but the removal of devirtualization for slot 167. There is no effect on the game. The same slot 167 and "field" in Noxious Plague and in other places also turned out to be a method call (the meaning of the method has not been established).
- **Shackles:** instead of a general guess, something specific was established: the modifier lookup now has a caster and ability filter. The function `0x45e0dd0` did not "lose logic", part of it was moved into `0x45e1810`.
- **Nature's Prophet:** the draft said "the filter was moved into the base function"; in fact the tree check in `area_of_effect` was removed, and the common coordinate filter remains.
- **Morphling Echo:** what the draft called "possibly" has been clarified:
