## Summary

### Main points
- There are almost no technical changes. The only substantive change is in `libtier0.so`: function 0x235370 now frees a temporary buffer directly via `free()`. Previously it did this with a virtual call to `g_pMemAlloc->Free` (slot 4, `[rax+0x20]`). This does not affect custom games or server plugins.

### Server and engine
- **`libtier0.so`, function 0x235370 (190 → 179 bytes).**
  - **What changed.** The result of the call to 0x138ee0 used to be freed via `g_pMemAlloc->Free`, and is now freed via `free()` (PLT 0x1410a0).
  - **What this call is.** It takes `(rdi, NULL, 0, &status)` and returns a buffer, which the function copies into a string and then frees. The signature looks like `abi::__cxa_demangle`. There is no symbol name in the data, so this is an inference from the shape of the call, not a confirmed fact.
  - **What this means.** If the call really returns a buffer from the system `malloc`, this is a fix: such a buffer must not be handed to the Source allocator. In that case the freeing no longer goes through a foreign allocator.
  - **Reliability.** The call replacement itself is confirmed by the code. The reason for the replacement is an assumption.
  - **Where it is called from.** No callers were found in the data (callers: 0). The impact on custom games has not been shown.
- There are no changes in `libengine2.so`.

### Schema and protocols
There are no technical changes to the schema or to scripts from the VPK. There are no changes to `.proto`.
