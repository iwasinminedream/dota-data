# Dota 6964: what changed

The report was generated automatically on 2026-10-20. The draft covering all changes (1 part) was written by Claude Haiku 4.5. Verification against the source data and the final version were done by Claude Opus 5.5 (both read-only). The tables below were computed without a model.

## Summary

### Highlights
- The patch is almost empty: there are no changes to the API, KV or game logic. libserver.so and libclient.so each have one changed function. The code size, strings and exports of both libraries did not change (so-diff.txt).
- **Two client console variables, `dota_audio_language_storage` and `dota_ui_language_storage`, had their flags changed.** They were `cl` and are now `cl, a, user`, that is, FCVAR_ARCHIVE | FCVAR_USERINFO (0x280). This is visible both in the libclient.so code (`xor ecx, ecx` → `mov ecx, 0x280` at registration) and in the console variable dump (previous-dump.txt and dumper/dump, lines 53182 and 54817). Both variables are now saved to the config, and, given the meaning of the USERINFO flag, their values should be sent to the server along with the client data. The default value of both is 8. The data does not make clear what exactly they store.
- A new interface string: a tooltip about buying additional slots in the **Avoided Players** list for Dota Shards. For now it exists only in english.json.
- In libserver.so, the function that handles Strange item counters (kill eater) changed only in the source line number in an Assert (29927 → 29931). The behavior of the function did not change.
- The removal of `ACT_DOTA_CAST5_STATUE` from the enum is dumper noise, not a game change (details below).

### New properties and methods: what they do
There are no new modifier properties, events, Lua/Panorama methods, behaviors or ability flags in this update: api-changes.txt contains only one removed enum value and one localization string.

The only new name is the localization key `PopupManageTeammates_Avoid_UpgradesPurchased_Tooltip`. It is not API:
- **What it does:** the tooltip "You've purchased {d:slots_purchased} additional slot(s), and can purchase another for {g:dota_shards_value:next_slot_cost}". The neighboring keys (`PopupManageTeammates_Avoid_Title`, `PopupManageTeammates_PurchaseAvoidSlot_Cost`, `PopupManageTeammates_Avoid_UpgradesPurchased`, `PurchaseFilteredPlayerSlot_Processing_Title` "Avoid More Players") show that it concerns buying additional slots in the avoided players list for Dota Shards.
- **In a custom game:** the key can be referenced from Panorama (`$.Localize`), but it is useless for custom games.
- **Evidence:** api-changes.txt; english.json, line 19291. The key is not yet present in other languages: german, russian and the rest have only `…_UpgradesPurchased` without `_Tooltip`. No strings were added in libclient.so (strings +0), so the key is used in Panorama markup from the VPK, not in code.
- **Reliability:** high.

### For custom game developers
- **Console variables:** the flags of `dota_audio_language_storage` and `dota_ui_language_storage` changed from `cl` to `cl, a, user`. files/convars.json already has the new flags, while api-changes.txt does not contain this change; the comparison tool missed it too. `dota_ui_language_storage` appeared in 6962, `dota_audio_language_storage` in 6938. Neither has a description. This does not break addons. I did not find a way to read a client's USERINFO variable from Lua in the API descriptions (files/vscripts), so do not rely on them on the custom game server.
- **`GameActivity_t` enum:** `ACT_DOTA_CAST5_STATUE` (1808) was "removed". This is noise, and here is why:
  - in dump-noise.md, two dumps of the same build differ in exactly this range of activities (1792–1811): `ACT_DOTA_CAST5_STATUE` is present in one dump and absent in the other, and the values of neighboring ACT_* entries are shuffled;
  - the same element appears and disappears in 30 of 87 files in files/changelogs (for example, 6942: "removed", value 1803);
  - the strings `ACT_DOTA_CAST5_STATUE` and `ACT_DOTA_CAST4_STATUE` are in neither libserver.so nor libclient.so, meaning these activities are registered dynamically when models are loaded.

  It is better not to hardcode numeric activity values above ~1790 in addons: use the names.
- There are no other modifiers, events, Lua or Panorama API, or removed or changed elements. Nothing can break in existing addons.

### Game code changes
In total, 2 functions changed; none were added or removed, and there are no "copies".

**libclient.so 0x5642140 (41227 → 41233 bytes) — the static initializer of the client translation unit. The logic is affected in only one place: the flags of two console variables.**
- **Whose function it is.** It is not the EventGrantDefinition handler, as Haiku wrote. The function contains guard bytes of static variables, registers the names of schema types (`EventGrantDefinition_*_t`, hashing with the murmur constant 0x5bd1e995) and registers dozens of console variables: `dota_allow_invalid_orders`, `dota_river_type`, `dota_joy_*`, `dota_camera_center`, `multiunit_x_*` and others. It is called from one place (0x565a730). Source: so-query func new.
- **What changed.** The fourth argument of the console variable constructor (ecx) is the flags. This is evident from the neighbors: `dota_river_type` → 0x4002 (DEVELOPMENTONLY | CHEAT), `dota_player_selection_cycle_ignores_groups` → 0x8080, `dota_allow_invalid_orders` → 0x4008. Two variables changed value:
  - `dota_audio_language_storage`: `xor ecx, ecx` → `mov ecx, 0x280`;
  - `dota_ui_language_storage`: the same. Verified via xref old/new: in the old build at address 0x564559c `xor ecx, ecx`, in the new one at 0x56455aa `mov ecx, 0x280`.

  The remaining ~760 lines of the diff are a reshuffling of instructions and registers (recompilation). There are no other new constants: the summary shows only +0x280 +0x280.
- **What this means in the game.** 0x280 = FCVAR_ARCHIVE (0x80) | FCVAR_USERINFO (0x200) according to the Source 2 flags table. The console variable dump independently confirms this: `cl` → `cl, a, user`. The selected interface and voice-over languages are now saved between launches and should be sent to the server with the client data. The data does not show why the server needs this.
- **Reliability:** high. Sources: the code and the dump, which agree.

**libserver.so 0x5086d00 (2392 bytes, 506 instructions) — Strange item statistics handling (kill eater). The logic did not change.**
- **Whose function it is.** The strings "!bCanIncrementStats" and "BaseKillEaterFound without stat tracking item." It is called from 0x5087670 (which contains the string "EconEntity_QueueKillEaterEvent") and calls `CItemSocket_Strange::vfunc#14/#21` and `CDOTAItemSchema::vfunc#53`. This is economy cosmetics (counters on Strange items), not gameplay.
- **What changed.** The only difference: `mov dword ptr [rbp-0x258], 0x74e7` → `0x74eb`. The constant is written into the Assert structure next to the pointer to the condition text "!bCanIncrementStats" ([rbp-0x260]) before the assert handler (0x3a346b0) is called with the message "BaseKillEaterFound…". So this is `__LINE__`: 29927 → 29931, the source file shifted by 4 lines above the assert. It is not an item index or an ID, as Haiku assumed.
- **What this means in the game.** Nothing. The code size is +0 bytes, and there are no other changed functions in the library. An edit to the source above the assert (comments or code that did not make it into this build) does not affect behavior.
- **Reliability:** high that the logic did not change. That it is specifically a line number: medium-high, since this is how Assert works and the constant sits next to the condition text.
