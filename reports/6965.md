# Dota 6965: что изменилось

Отчёт создан автоматически 2026-10-20. Черновик по всем изменениям (1 частей) — Claude Haiku 4.5, проверка по исходным данным и итог — Claude Opus 5.5 (оба только с правом чтения); таблицы ниже посчитаны без модели.

## Сводка

### Главное

- Это техническая сборка (6965, build 26090992), игровых изменений нет. В `libserver.so` поменялась одна функция из 220000, ничего не добавлено и не удалено. Строки и экспорт те же, размер кода +0 байт. Остальные библиотеки, включая `libclient.so`, не менялись (`so-query libs`).
- Единственная настоящая правка в коде — ИИ ботов для Sand King → Burrow Strike (`CDOTA_Bot_AbilityUsage_SandKing_BurrowStrike::vfunc#5`). Значение `burrow_width` теперь читается целочисленным геттером спецзначений (дробная часть отбрасывается) вместо дробного. Число получается то же самое. Но пропадает отладочное предупреждение `AlertSpecialValueFloatIntoInteger` («Reading FIELD_FLOAT value … into an integer container … will cause truncation»). Поведение ботов практически не меняется (подробно — в разделе «Изменения в коде игры»).
- Новый член перечисления `ACT_DOTA_CAST5_STATUE = 1801` в Lua API — это шум дампера, а не нововведение (см. ниже).

### Новые свойства и методы: что делают

Настоящих новых свойств, событий, методов, флагов и поведений в этой сборке нет.

- **`ACT_DOTA_CAST5_STATUE` (GameActivity_t, 1801)** — нововведением не является. На чём основан вывод:
  - **Это не новинка.** В `files/changelogs/*.json` эта активность то «добавляется», то пропадает десятки раз (6715, 6718, 6730, 6733, 6750, 6758, 6761, 6763, 6789–6791, 6807, 6831, 6877, 6944…), и каждый раз с другим значением: 1794–1806. Так же ведут себя `ACT_DOTA_VOODOO_REST` и `ACT_DOTA_SPWN`.
  - **Значения нестабильны внутри одной сборки.** По `dump-noise.md`, два дампа этой же сборки различаются в `cl_script_reload`: `ACT_DOTA_CAST5_STATUE` там 1801 и 1806, номер 1801 в другом дампе занимает `ACT_DOTA_VOODOO_REST`, а `ACT_DOTA_SPWN` вообще пропадает. Все значения выше ~1779 у этих активностей перемешиваются.
  - **Сравнение дампов это подтверждает.** В прошлом сыром дампе есть `ACT_DOTA_SPWN = 1803` и `ACT_DOTA_VOODOO_REST = 1808`, а `CAST5_STATUE` нет. В текущем всё наоборот.
  - **Вывод.** Номера активностей из этого диапазона, судя по всему, назначаются при загрузке и не постоянны. Надёжность вывода высокая. На числа 1792–1811 в кастомках полагаться нельзя: используйте имя константы, а не литерал.

### Для разработчиков кастомок

- Изменений в Lua API, Panorama, событиях, модификаторах и консольных переменных нет. `api-changes.txt` содержит только шумовое `ACT_DOTA_CAST5_STATUE` (см. выше).
- Существующим аддонам ничего не грозит. Есть одна оговорка: если код сравнивает активность с числовым литералом из диапазона ~1780–1811 (статуи, `ACT_DOTA_RELAX_*`, `ACT_DOTA_RUN_ALT`, `ACT_DOTA_CAST_FENCE` и т. п.), он мог ломаться и раньше — номера плавают от сборки к сборке. В `files/vscripts/enums.json` из этого диапазона сейчас есть только `ACT_DOTA_DEFEAT_STATUE` (1794), `ACT_DOTA_CHANNEL_STATUE` (1795) и `ACT_DOTA_CAST5_STATUE` (1801), то есть список неполный.

### Изменения в коде игры

**`CDOTA_Bot_AbilityUsage_SandKing_BurrowStrike::vfunc#5`** (libserver.so, новый адрес 0x5f3dd30, старый 0x5f45910; 2099 → 2107 байт, 469 → 471 инструкция). Это логика ботов: оценка, стоит ли применять Burrow Strike и куда.

- **Что изменилось.** Сразу после чтения `"burrow_width"` вызывается другой геттер спецзначения:
  - Было: `call 0x3a5fbf0`, результат берётся из `eax` (`mov r13d, eax`). Это целочисленный вариант геттера, его используют около 551 места. Внутри он вычисляет float, усекает его (`cvttss2si`) и, если значение дробное, вызывает 0x3a5f890. Там стоит алерт `"AlertSpecialValueFloatIntoInteger"` с текстом «CDOTABaseAbility: Reading FIELD_FLOAT value for '%s' into an integer container for ability '%s', will cause truncation.» (текст собран из констант `movabs`).
  - Стало: `call 0x3a5f0a0`, результат берётся из `xmm0` (`movd r15d, xmm0`). Это float-вариант геттера, около 575 мест. Затем идёт явное усечение `cvttss2si eax, xmm6` перед передачей.
  - Остальные отличия — смена регистров (r13/r14/r15) и порядок инструкций, то есть перекомпиляция.
- **Куда передаётся значение.** Ширина уходит стековым аргументом в общую функцию 0x5ef4fa0. Это поиск лучшей линии для ударов по линии у ботов, её же вызывают Jakiro Dual Breath / Ice Path / Macropyre, Earthshaker Fissure и Windrunner Powershot. Внутри аргумент возводится в квадрат (`imul r14d, r14d`) и сравнивается с квадратами расстояний до целей.
- **Константы.** Без изменений: 200 (добавка к дальности каста), 1000, 0.75, 100.
- **Сверка с KV.** В `files/abilities.json` у `sandking_burrowstrike` `burrow_width = 150` с `affected_by_aoe_increase: 1`. С бонусом к радиусу ширина может стать дробной — тогда старый код как раз вызывал алерт.
- **Что это значит в игре.** Ширина для ботов считается так же (усечение в обоих случаях), исчезает только ложное предупреждение. На игроков и кастомки не влияет.
- **Надёжность.** Высокая для факта замены геттера и её последствий: проверено по `func old/new` обоих геттеров и вызываемой функции. Что именно Valve хотела исправить, по коду не видно — предположительно предупреждение при бонусах к AoE.

### Бинарники

- Снимки 6964-11146732 → 6965-11152239. Изменился только `dota-bin/libserver.so`: 126.6 МБ → 126.6 МБ, код +0 байт, строки +0/−0, экспорт +0/−0. Сдвиги адресов функций (у этой −0x7be0) — следствие перекомпиляции.
- Изменений движка, сети, клиента и интерфейса нет. Изменений API, за которыми стоял бы код, тоже нет.

<details><summary>Что Opus исправил в черновике Haiku</summary>

- Haiku написал, что функция Burrow Strike изменилась только из-за перераспределения регистров и «логика не изменилась». Это неверно: в исходнике поменялся вызываемый геттер `burrow_width`, с целочисленного на float с явным усечением. Численно результат тот же, но пропадает алерт `AlertSpecialValueFloatIntoInteger`.
- Haiku не объяснил, почему `ACT_DOTA_CAST5_STATUE` — шум. Добавлены доказательства: история changelogs, контрольный дамп, сравнение со старым дампом.
- Добавлены разбор общей функции поиска линии для ботов (0x5ef4fa0) и сверка с KV (`burrow_width = 150`, `affected_by_aoe_increase`).

</details>
