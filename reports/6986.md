# Dota 6986: что изменилось

Отчёт создан автоматически 2026-11-20. Черновик по всем изменениям (частей: 3) — Claude Sonnet 5.5, проверка по исходным данным и итог — Claude Sonnet 5.5 (только с правом чтения); таблицы ниже посчитаны без модели.

## Сводка

### Главное

- **Morphling, Replicate (улучшение Aghanim's Scepter), эхо:** основной контент сборки 6986. Эхо научили копировать **Tusk Snowball**. Оригинал докатывает windup, и только потом появляются эхо, а их собственный windup обнуляется. Основания: новые поля схемы `m_hPendingSnowball*`, функции в `libserver.so` и native-свойства эха (подробности в следующем разделе).
- **Morphling, эхо:** переписано несколько других правил.
  - Появился чёрный список способностей, которые эхо не повторяет: 17 имён, сами имена из `.so` не извлеклись.
  - Эхо не исчезает, пока оно в движении (`modifier_hoodwink_arcing_boomerang`, `modifier_marci_lunge_*`, `modifier_death_seeker_out_of_world`, `modifier_tusk_snowball_movement`) или пока на цели активен `modifier_grimstroke_spirit_walk_buff`.
  - Новый виртуальный метод способностей (слот 241) копирует состояние способности в копию эха.
  - `MODIFIER_PROPERTY_STATUS_RESISTANCE_CASTER` теперь равно `100 - echo_power`, а было `echo_power - 100`. Это согласуется с подсказкой: каждое следующее эхо должно накладывать более короткие баффы и дебаффы.
- **Shadow Shaman, Shackles:** поиск `modifier_shadow_shaman_shackles` теперь идёт с фильтром «кастер + способность». Раньше фильтра не было. Правка в `OnChannelThink`, `OnChannelFinish` и в новой вспомогательной функции, вынесенной из старого блока.
- **Rubick, Spell Steal:** у `Beastmaster_SummonThunderhide` и `Chen_Zealot` появились собственные `OnUnStolen`. Судя по коду, при потере украденной способности они убирают или убивают созданных ею юнитов (вывод умеренной надёжности).
- **Nature's Prophet, Nature's Call (`furion_force_of_nature`):** с клиента убрана собственная проверка `CastFilterResultLocation`. Она считала деревья в `area_of_effect` и иначе возвращала ошибку. Теперь остаётся только общая проверка валидности точки. Серверный код способности не менялся.
- **Ogre Magi, Bloodlust:** подмена атаки-скорости на `self_bonus` для кастера перенесена из `OnCreated`/`OnRefresh` в геттер свойства. Итоговое значение то же.
- **Остальное:** обновление текстов (80 файлов локализации в VPK) и большой объём «шума» перекомпиляции. В классах схемы изменились только два морфлинговых модификатора. Новых событий, enum и констант API нет.

### Новые свойства и методы: что делают

Все три записи из `api-changes.txt` относятся к `modifier_morphling_replicate_echo`. Сами константы не новые: они были в `enums.json` и `modifier_properties.json` (`HasFunction = true`) и упоминаются в `previous-dump.txt`. Новое — то, что их реализует этот встроенный модификатор. Остальное ниже — новые методы и поля, найденные по коду.

**`MODIFIER_PROPERTY_OVERRIDE_ABILITY_SPECIAL`** (`GetModifierOverrideAbilitySpecial`, сервер)
- **Что делает:** возвращает 1 («это значение переопределяю») только если способность называется `tusk_snowball` и запрашиваемый special — `snowball_windup`. Иначе возвращает 0.
- **Основание:** дамп и дизассемблер `0x44a4140`. Он сравнивает `[ability+0x840]` со строкой `tusk_snowball`, а имя special в событии (`ability_special_value`) — со строкой `snowball_windup`. Дамповая «формула» в `api-changes.txt` с `? == 0 ? 1 : 0` — мусор декомпиляции.
- **Как пользоваться:** в Lua-модификаторе реализуйте пару `GetModifierOverrideAbilitySpecial(event)` и `GetModifierOverrideAbilitySpecialValue(event)`. Поля события: `ability`, `ability_special_value`, `ability_special_level`. Первая функция говорит, что special переопределён, вторая отдаёт число.
- **Надёжность:** высокая для самой функции, средняя для интерпретации. Назначение выводится из сочетания с остальным кодом.

**`MODIFIER_PROPERTY_OVERRIDE_ABILITY_SPECIAL_VALUE`**
- **Что делает:** константа 0 (дамп).
- **Вывод:** вместе с предыдущим пунктом `snowball_windup` для копии `tusk_snowball` в эхе равен 0. Эхо-снежок стартует без windup (в KV `snowball_windup` = 3). Параллельно оригинальный Tusk ждёт обычный windup.
- **Надёжность:** средняя.

**`MODIFIER_EVENT_ON_MODIFIER_REFRESHED`** (`OnModifierRefreshed`, сервер)
- **Что делает:** новый обработчик `0x44be040`. Его уточнения ниже даны с низкой надёжностью, суть дана по логике кода.
  - Реагирует на обновление чужого модификатора, если цель — `m_hDebuffTarget` эха.
  - Сверяет имя способности модификатора со способностью эха (`<NoAbilityName>` при отсутствии).
  - Ищет в таблице записей по `[modifier+0x50]` и для найденной записи вызывает `SetDuration(...)` с сохранённой длительностью.
- **Таблицу пишет** `GetModifierStatusResistanceCaster` (`0x44a83a0`). Она снимает снимок модификаторов цели (id, длительность, остаток) в вектор по `+0x1b18`, а возвращает `100 - echo_power` (`+0x1b30`).
- **Вывод:** эхо не должно уменьшать или продлевать уже висящие дебаффы своим ослабленным накладыванием. Это гипотеза.
- **Надёжность:** низкая.

**`MODIFIER_PROPERTY_STATUS_RESISTANCE_CASTER`** (изменено)
- **Что изменилось:** формула была `echo_power - 100`, стала `100 - echo_power`. Подтверждено дампом и кодом `0x44a83a0`: `100.0 - [+0x1b30]`.
- **Смысл:** положительное значение сокращает длительность накладываемых эхом эффектов. Совпадает с локализацией `scepter_description` («applying shorter buffs/debuffs»).
- **Надёжность:** высокая.

**Новые поля схемы** (`SchemaSystem`, смещения подтверждены кодом)
- `CDOTA_Modifier_Morphling_Replicate_Echo.m_hDebuffTarget` (`CHandle<CBaseEntity>`, @6932 = `0x1b14`). Читается в `OnModifierRefreshed`.
- `CDOTA_Modifier_Morphling_Replicate_Echo_Source`:
  - `m_hPendingSnowball` (@6904 = `0x1af8`);
  - `m_hPendingSnowballTarget` (@6908 = `0x1afc`);
  - `m_flPendingSnowballWindupEnd` (`GameTime_t`, @6912 = `0x1b00`).
- Надёжность высокая: схема, имена в `.so` и обращения в `0x4513610` / `0x4513820` совпадают.

**Логика отложенного эхо-снежка** (`Echo_Source`)
- **`0x4513610`** — тело обработчика `Echo_Source::vfunc#97` (в нативных модификаторах это `OnAbilityFullyCast`). Если применена `tusk_snowball`, он запоминает способность и цель в `m_hPendingSnowball*`. Время окончания windup считается как `GameRules time + GetSpecialValueFor("snowball_windup")`. Включается `StartIntervalThink(0)`. Иначе сразу вызывается создание эха `0x4512ee0`.
- **`Echo_Source::OnIntervalThink`** (`0x4513820`, новый): ждёт, пока у Morphling есть `modifier_tusk_snowball_movement`. Если способности `tusk_launch_snowball` нет, её флаг `[+0x7a6]` равен 0 или время ≥ `m_flPendingSnowballWindupEnd`, создаёт эхо через `0x4512ee0`. Затем сбрасывает handle и вызывает `StartIntervalThink(-1)`. Если модификатор движения исчез, состояние просто очищается.
- Надёжность умеренная: смысл флага `+0x7a6` не определён.

**Способности: слот `vfunc#241`** (новый виртуальный метод «скопировать состояние способности в копию для эха», умеренная надёжность)
- Реализации: `Bane_Nightmare`, `Muerta_DeadShot` (было 81 байт, стало 305), `Tusk_WalrusKick` (369 байт), `Marci_Companion_Run` (32 байта).
- `Tusk_WalrusKick` (разобран подробно): аргументы — оригинал, копия, ещё один параметр. Если у владельца найдена способность `morphling_replicate`, копируется вектор +0x860/+0x868 (полученный вектор цели/направления). Иначе вектор пересчитывается относительно позиции другого юнита.
- `Marci_Companion_Run` просто копирует поле `+0x884/+0x88c`. Надёжность умеренная.

**Способности: слот `vfunc#239`**
- `Marci_Companion_Run::vfunc#239` раньше всегда возвращал 0, теперь возвращает байт `+0x858` способности.
- Этот байт выставляет в 1 `0x44df160` (`Echo`) на время вызова каста копии и сбрасывает в 0 после. Это признак «способность сейчас кастуется эхом».
- Надёжность средняя: назван ли слот в движке так, неизвестно.

**Прочие новые функции:**
- `CDOTA_Ability_Beastmaster_SummonThunderhide::OnUnStolen` (`0x4667890`) и `CDOTA_Ability_Chen_Zealot::OnUnStolen` (`0x482dbf0`):
  - Оба после базового `OnUnStolen` берут сохранённые handle'ы, проверяют, что юнит жив, и вызывают `0x61b8120`.
  - Эту же функцию зовут `OnDestroy` у `Juggernaut_Healing_Ward_Aura`, `Lich_Ice_Spire` и `Morphling_Replicate_Echo::OnDestroy`. Поэтому это скорее удаление или убийство юнита, но точное имя неизвестно.
- Новые идентификаторы в `libserver.so` (`strings +4`): `m_flPendingSnowballWindupEnd`, `m_hDebuffTarget`, `m_hPendingSnowball`, `m_hPendingSnowballTarget`. Это поля схемы, не API.

### Для разработчиков кастомок

- **Lua API и Panorama:** изменений нет. Новых функций, событий и констант тоже нет. Удалений и переименований тоже нет. `OVERRIDE_ABILITY_SPECIAL`, `…_VALUE` и `ON_MODIFIER_REFRESHED` существовали и раньше, а эта сборка добавила только их реализацию во встроенном `modifier_morphling_replicate_echo`. Если ваш аддон использует эту пару для Tusk Snowball, поведение будет таким же, как у эха. Ограничение: `HasFunction` для этих свойств равен `true` — движок вызывает их у Lua-модификаторов.
- **Что может сломать существующие аддоны:**
  - Кастомки с Morphling, у которых есть Scepter и Replicate:
    - эхо теперь не копирует способности из чёрного списка (список не извлечён);
    - эхо не удаляется, пока Morphling-иллюзия в движении;
    - длительность баффов и дебаффов эха стала короче (знак `STATUS_RESISTANCE_CASTER`);
    - у Tusk Snowball поведение эха заметно изменилось.
  - Кастомки с Shadow Shaman: Shackles теперь считает и снимает только свои модификаторы, а не любые с этим именем. Если у вас несколько Shackles на одной цели (например, два героя или Rubick), поведение изменится.
  - Кастомки с Rubick и украденными `beastmaster_summon_thunderhide` / `chen_zealot`: при потере способности теперь срабатывает очистка (по коду), раньше её не было.
  - Кастомки с Nature's Call: клиентская проверка наличия деревьев в зоне убрана. Сервер всё ещё ограничивает число треантов числом деревьев, как сказано в локализации.
- **Консольные переменные, схема сетевых событий:** новых нет.
- **Шум дампера** (`cl_script_reload`, `ACT_DOTA_*`, `muerta_debut_satyr_*`): отнесён к нестабильным, по `dump-noise.md` это не изменения игры.

### Изменения в коде игры

Всего `libserver.so`: 334 функции изменены, 20 добавлены, 6 удалены, 17 «копий кода». `libclient.so`: 6 / 1 / 2 и 7 копий. `libtier0.so`: 3 изменены. Полный список: `reports/6986-functions.md` и `so-query.py funcs`.

**Morphling Replicate (подробно, сервер)**
- `Replicate_Echo::OnIntervalThink` (`0x44df4d0`, 198 → 700 байт; ≈ «первый тик»).
  - Первый тик теперь считает время жизни как `now + scepter_echo_visible_duration` (поле стало `+0x1b34`) и вызывает `0x44df160` (каст эха).
  - Потом, если на эхе (родителе) нет `modifier_item_lotus_orb_channel_check`, проверяется занятость: есть ли `modifier_tusk_snowball_movement`, `modifier_death_seeker_out_of_world`, `modifier_hoodwink_arcing_boomerang`, `modifier_marci_lunge_tracking_motion`, `modifier_marci_lunge_arc`, а также `modifier_grimstroke_spirit_walk_buff` на цели (`echo_target`).
  - Если что-то из этого есть, время жизни сдвигается заново: `0.5 + visible_duration`. Через виртуальные вызовы `+0x1f8` и `+0x2f8` (GetRemainingTime/SetDuration — предположительно) продлеваются сам модификатор и `modifier_illusion`.
  - Иначе по истечении времени вызывается удаление (`0x5057660`, как в старом коде).
  - Надёжность высокая по структуре, средняя по именам виртуальных вызовов.
- `0x44df160` — строка вызова каста эха. Добавлены `byte [ability+0x858] = 1` перед кастом и `= 0` после. Надёжность высокая.
- `0x44dee60` (внутри блока `0x44ddd80`, 4483 → 4662 байта): фильтр «можно ли эху повторить эту способность».
  - Не пассивная, поведение с битом `8` (предположительно UNIT_TARGET), поле `+0x54` типа не равно 1.
  - Новое: имя способности сравнивается с таблицей из 17 имён (8 байт на указатель по `0x7f1c340`), при совпадении повторять нельзя. Раньше функция просто возвращала `state != 1`.
  - Список имён из `.so` без данных релокаций не извлечь. Надёжность высокая для структуры, имён нет.
- `Echo_Source` создание эха (`0x4512ee0`, 1677 → 1839 байт): проверки handle вынесены в вызывающий код. Добавлено: после создания иллюзии ищется `ogre_magi_multicast`, и если она есть, вызывается виртуальный метод слота 245 с аргументом 0. Вероятно, Multicast эху отключается или сбрасывается. Это гипотеза.
- `Echo_Source::vfunc#97` и `OnIntervalThink` — см. раздел про отложенный снежок выше.
- Классы: `Echo` вырос на 24 байта, `Echo_Source` на 16. В конструкторах и `CModifierFactory<…>::vfunc#0` новые размеры `0x1b38` и др. `Echo` содержит вектор по `+0x1b18/+0x1b20/+0x1b28` (элементы по 12 байт), которого нет в схеме.
- `Replicate_Echo::vfunc#97` (`0x445a320`) — просто таблица регистрации свойств: добавились три новых слота (`OVERRIDE_ABILITY_SPECIAL` и др.). Три маленьких геттера читают `echo_power` по новому смещению `0x1b30`.
- Склейка и копии: `0x4492c30`, `0x44930e0`, `0x4485390`, `0x447d460` (удалена, заменена тремя новыми функциями).

**Shadow Shaman, Shackles (сервер)**
- `OnChannelThink`, `OnChannelFinish`, новая `0x45e1810` (860 байт, вызывается из `OnSpellStart`): поиск модификатора теперь `FindModifierByNameAndCaster(target, "modifier_shadow_shaman_shackles", GetCaster(), ability)` вместо `(…, 0, 0)`. Это справедливо для проверки, снятия и подсчёта максимальной оставшейся длительности.
- `0x45e0dd0` (1609 → 784 байта): из неё вынесен блок «максимальная оставшаяся длительность по цепи; запись в сетевое поле `+0x85c`» и стал самостоятельной функцией `0x45e1810`. Собственной логики она не потеряла.
- Надёжность: высокая для самих вызовов; игровой эффект выведен из названий.

**Nature's Prophet (клиент)**
- Удалена `C_DOTA_Ability_Furion_ForceOfNature::CastFilterResultLocation` (`0x4a1efd0`). Она считала сущности (деревья) в `area_of_effect` через `0x4a1ec40`, при их отсутствии возвращала код 23, иначе передавала общей проверке. Теперь слот указывает на общий `0x4f7cc30` (отбой, только если координаты равны `FLT_MAX`, код 24). Серверных изменений нет.

**Ogre Magi, Bloodlust** (клиент `0x4bee4d0`, сервер `0x4bf1260`)
- Из `OnCreated`/`OnRefresh` убрана ветка `if (GetCaster() == GetParent()) [0x1af8] = [0x1b00]`. Появились геттеры (`0x4b36490` сервер, `0x4b95910` клиент): если `GetCaster() != GetParent()` отдаётся `bonus_attack_speed` (`+0x1af8`), иначе `self_bonus` (`+0x1b00`). В KV `self_bonus` для Ogre Magi — `40 60 80 100`.
- Итог по значению тот же, но вычисляется на лету, а не при создании и обновлении.
- Надёжность: высокая. Какое именно свойство отдаёт геттер (`vfunc#97` сервер, `vfunc#88` клиент), не проверялось.

**Huskar, Berserker's Blood** (клиент `0x49f47a0`, 680 → 803 байта)
- Это не новая формула. Прежде отдельная функция (`0x4a14b90`) уже считала `((clamp((v-lo)/(hi-lo),0,1)·100)^1.85) / 100^1.85` через `V_powf`. Теперь она встроена в тело. Константы 100, 1 и 1.85 были в старой функции. Логика не менялась. Надёжность высокая.

**Venomancer, Noxious Plague** (`0x4773f80`)
- Перед наложением `modifier_venomancer_noxious_plague_contagious` добавлена проверка виртуального метода `vfunc#167` (`+0x538`) цели; при `false` заражение пропускается. Плюс небольшой новый путь с `r15-1`.
- Что именно проверяет слот 167, не установлено; по другим местам (`Echo` каст, `OnUnStolen`) это булева проверка «юнит годен» (предположительно жив). Надёжность низкая.

**Прочее заметное**
- `Windrunner_UnfocusedFire::vfunc#97` (`0x45a6db0`): вызов через глобальный интерфейс стал виртуальным (`+0x80`, добавлен аргумент `0x68`), плюс `vfunc#8` у объекта. Что вызывается, не определено.
- Блок кастомизации оберегающих предметов: `0x5c03fe0` (строки `npc_dota_observer_wards`, `npc_dota_sentry_wards`; константа 150). Новый путь добавляет два виртуальных вызова (слоты 269 и 271) и работает с `[this+8]`. Смысл (прибавка к дальности каста варда по уровню предмета?) не определён.
- `Broodmother_Spider_HP::vfunc#97` (`0x48565c0`): добавлена цепочка проверок (тип 3, флаг `+0xd3c`, `+0x175a == 0`) для хозяина-героя и сравнение слота 427 с известным адресом. Смысл не определён.
