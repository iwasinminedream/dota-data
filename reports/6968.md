# Dota 6968: что изменилось

Отчёт создан автоматически 2026-10-26. Черновик по всем изменениям (1 частей) — Claude Haiku 4.5, проверка по исходным данным и итог — Claude Opus 5.5 (оба только с правом чтения); таблицы ниже посчитаны без модели.

## Сводка

### Главное

- **В API изменений нет.** Файл `api-changes.txt` пуст: Lua API, Panorama, события, модификаторы и константы по дампу не менялись. 11 констант `ACT_DOTA_*`, `muerta_debut_satyr_*` и `radiant_melee_mars_shieldbash` с другими числами — это шум дампера (`dump-noise.md`), а не изменение игры.
- **libclient.so не изменилась.** Изменено 0 функций из 280912. В libserver.so изменены 3 функции из 220000, ни одна не добавлена и не удалена. Строки и экспорт обеих библиотек не изменились (`so-diff.txt`).
- **Исправлен MegaMeepo (Meepo).** Когда с клона снимается `modifier_meepo_megameepo` (клон слезает с плеч или его бросают), игра теперь явно делает его снова видимым: снимает флаг EF_NODRAW. Вероятно, это исправление бага с невидимым клоном. Это единственное изменение логики в сборке.
- **Legion Commander, Press The Attack: поведение не изменилось.** Код пересобран: добавление цели в список вынесено в общую функцию. Константы и условия те же.
- **Muerta: не логика.** Изменился код, который регистрирует сетевую переменную `m_hDoubleShotTarget`: компилятор по-другому собрал хеш имени класса.

Обращайтесь к ним по имени (`ACT_DOTA_TORRENT`), а не по числу.

### Изменения в коде игры

**1. `CDOTA_Modifier_Meepo_MegaMeepo::OnDestroy`** (libserver.so, было 0x49e5640 → стало 0x49e56a0, 703 → 743 байта)

- **Чей модификатор.** `modifier_meepo_megameepo`, его носят клоны, сидящие на основном Meepo. Это видно по подсказке «Основной герой может бросить этого клона» и по KV `meepo_megameepo` / `meepo_megameepo_fling`.
  - `OnCreated` крепит клона к точке `attach_megameepo_%d`.
  - `OnDestroy` отцепляет его (вызов `0x3b1b440(parent, 0, 0, 0)`), затем отбрасывает от основного Meepo: `modifier_knockback` с `end_knockback_duration`, `end_knockback_distance`, `end_knockback_height`.
- **Что добавилось.** Сразу после отцепления добавлены такие шаги:
  - `parent = GetParent()`;
  - `parent->SetEffects(parent->m_fEffects & ~0x20)` — поле +0x6c0, виртуальный слот 215 (+0x6b8);
  - вызов `0x540dc30(parent)`.
  
  Остальной код не изменился.
- **Почему это «показать юнит».**
  - Поле +0x6c0 — это `m_fEffects`: в сетевой схеме строка `"m_fEffects"` регистрируется со смещением `0x6c0` (xref на 0x3d726f8).
  - Бит 0x20 — это `EF_NODRAW`: в перечислении Lua API `EF_NODRAW = 32`.
  - Ровно такая же последовательность (`and 0xffffffdf` → `call [rax+0x6b8]` → `jmp 0x540dc30`) стоит в `CDOTA_Modifier_Generic_Hidden::OnDestroy` и `CDOTA_Modifier_Phoenix_SupernovaHiding::OnDestroy`.
  - `0x540dc30` вызывают ещё 113 функций, почти все они возвращают юнит в мир: Puck Phase Shift, Pudge Swallow, Riki Tricks of the Trade, Void Spirit Dissimilate, Monkey King, `CDOTA_BaseNPC::Spawn` и другие.
- **Что это значит в игре.** Клон Meepo после MegaMeepo больше не может остаться невидимым (без отрисовки). Кто ставил ему EF_NODRAW, я в коде не нашёл: в `OnCreated` и `OnIntervalThink` этого модификатора такой записи нет. Значит, это скорее страховка от бага, когда клон слезает «невидимым», чем новая механика.
- **Надёжность.** То, что код снимает EF_NODRAW с клона, установлено надёжно. Повод для правки (какой именно баг) — догадка. Что делает `0x540dc30` по сути, точно не установлено: это общий вызов «после показа юнита».

**2. `CDOTA_Ability_Legion_Commander_PressTheAttack::OnSpellStart`** (было 0x4a7bdb0 → стало 0x4a6daf0, 1618 → 1501 байт)

- **Что делает функция.**
  - Если `radius` > 0, ищет юнитов в радиусе (`FindUnitsInRadius`, флаг `0x13`).
  - Проверяет, есть ли в списке цель и сам Legion Commander, и добавляет недостающих.
  - Всем юнитам из списка вешает `modifier_legion_commander_press_the_attack` (константа `100` та же), запускает частицу `..._aoe.vpcf` и звук.
- **Что поменялось.** Раньше добавление в `CUtlVector<EHANDLE>` было встроено в саму функцию: `add r8d, 1`, `add eax, 1`, два `mov esi, 1` перед расширением массива. Теперь вместо этого вызывается общая функция `0x4a6b8b0`. Её же вызывают `Ogre_Magi_Smash::OnSpellStart`, `Ogre_Magi_Bloodlust::OnSpellStart`, `Medusa_MysticSnake` и код Muerta (DoubleShot). Отсюда «−1 −1 −1 −1» в сводке: из функции ушли четыре единицы, они переехали в `0x4a6b8b0`. Значения и проверки не изменились, остальное — смена регистров и слотов стека.
- **Что это значит в игре.** Ничего, поведение то же.
- **Надёжность.** Высокая.

**3. Функция без имени 0x4aa79f0 (Muerta, `m_hDoubleShotTarget`)** (было 0x4aa7a30, 3290 → 3322 байта)

- **Что это.** Регистрирует сетевую переменную `CNetworkVarBase<CHandle<CBaseEntity>, CDOTA_Unit_Hero_Muerta::NetworkVar_m_hDoubleShotTarget>`, вызывающих у неё нет. Это не игровая логика.
- **Что поменялось.** Раньше хвост имени класса `"CDOTA_Unit_Hero_Muerta"` (байты 20–21, `"ta"`) хешировался вызовом функции (`lea rdi, [r13+0x14]; call`). Теперь этот шаг MurmurHash2 встроен прямо в код: `xor 0x6174` («ta»), `imul 0x5bd1e995`, `shr 0xd`/`0xf`. Начальное значение `0x31415930` = `0x31415926 ^ 22` (длина имени). Хеш получается тот же.
- **Что это значит в игре.** Ничего, двойной выстрел Muerta не изменился.
- **Надёжность.** Высокая.

<details><summary>Что Opus исправил в черновике Haiku</summary>

- **MegaMeepo.** У Haiku флаг 0x20 снимается «у модификатора knockback», а «+0x6c0» — «новое поле». На деле снимается EF_NODRAW в `m_fEffects` (поле не новое) у самого клона-носителя модификатора, то есть клон делается видимым. Описание игрового эффекта переписано и подтверждено сравнением с Generic_Hidden и Phoenix SupernovaHiding.
- **Press The Attack.** У Haiku «четыре константы уменьшены на 1» и «переработана логика поиска целей, возможно изменены условия». Это неверно: убраны четыре единицы из встроенного добавления в вектор, которое теперь вызывается как общая функция. Логика не изменилась.
- **Muerta.** У Haiku «изменена валидация двойного выстрела, добавлена проверка целостности или кэширование». Это неверно: это регистрация сетевой переменной, где компилятор встроил хеш имени класса. Логика не изменилась.
- Шум дампера (`ACT_*`) Haiku определил верно. Вывод «нового API нет» подтверждён: `api-changes.txt` пуст, новых строк и символов нет.

</details>
