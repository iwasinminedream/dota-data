# Dota 6969: What Changed

The report was generated automatically on 2026-10-27. The draft covering all changes (1 part) was written by Claude Haiku 4.5; verification against the source data and the final version were done by Claude Opus 5.5 (both read-only). The tables below were computed without a model.

## Summary

### Highlights

- **The update is almost entirely server-side: Beastmaster.** The API, strings and library exports did not change (api-changes.txt is empty; in so-diff both .so files show "strings +0 −0, exports +0 −0"). Logic changed only for Beastmaster and Hoodwink. The other changed functions are recompilation.
- **Beastmaster's global talent auras no longer come from illusions.** This concerns `special_bonus_unique_beastmaster_5` (+15 movement speed, KV `bonus_ms`) and `_6` (+250 health, KV `bonus_hp`). Previously `GetAuraRadius` always returned −1, i.e. a global radius. Now it returns 0 if the bearer has the illusion flag set. On the client the check goes through the virtual IsIllusion, on the server through the byte at +0x16d2.
- **Beastmaster's auras now identify "their own" units by player ID.** Previously the pointer to the player controller was compared (slot 395); now the owner player's ID is compared (slot 396). This affects Inner Beast, Drums of Slom and both talents: the aura's target filter, the unit count for Inner Beast, and the choice of whom Drums of Slom heals.
- **Hoodwink: the Decoy illusion is created with `permit_illusion_recycling = 0`.** All other abilities that set this key pass 1.
- **HUD rune ping, Death Prophet Exorcism, Ember Spirit Fire Remnant, Dawnbreaker Solar Guardian, courier, farm bot, registration of `C_DOTA_Ability_Riki_Backstab`.** These only have blocks rearranged, different inlining and different registers. The logic in the code did not change.

### New properties and methods: what they do

There are no new properties, events, methods, flags or ability behaviors in this build.
- api-changes.txt is empty.
- No strings were added to the .so files (so-diff: "strings +0 −0"), no exports, no functions (func-diff: "added 0, removed 0").
- Reliability: high.

The only "new name" in the code is the string `permit_illusion_recycling` in Hoodwink Decoy. But this is not a new API: the illusion parameter table key existed in the previous build too; it was referenced in 16 places, now 17. It is covered in the section "Changes in the game code".

### For custom game developers

- **Lua API, Panorama, events, modifiers, console variables:** no changes (api-changes.txt is empty). Ordinary addons should not be broken by this update.
- **Dumper noise, not a game change** (dump-noise.md). The numeric values of some `ACT_*` differ even between two dumps of the same build: `ACT_DOTA_CAST_FENCE`, `ACT_DOTA_CYCLONE`, `ACT_DOTA_RELAX_IN/OUT`, `ACT_DOTA_SPWN`, `muerta_debut_satyr_*`, `radiant_melee_mars_shieldbash`, and others. Do not hardcode the numbers from the dump for these activities; use the names.
- **If your custom game has Beastmaster abilities** (`beastmaster_inner_beast`, `beastmaster_drums_of_slom`, `special_bonus_unique_beastmaster_5/6`):
  - A unit's belonging to Beastmaster is now determined by the owner player's ID, not by the pointer to the player controller.
  - The ID is obtained as follows: for a unit with a hero owner, it is that hero's ID. Otherwise, if the unit has flags 0x20100 set, it is the field at +0x1014. In all other cases, −1.
  - A possible consequence, not verified in the code: units without a hero owner whose player ID is set in another way (for example, via `SetControllableByPlayer`) may now be considered "their own". They would then receive the auras, Drums healing, and be included in the Inner Beast count.
  - Talents 5/6 no longer provide auras from illusions. This also applies to illusions created via `CreateIllusions`.
- **Illusions:** `permit_illusion_recycling` is a key in the illusion parameter table that the engine reads when creating illusions. It is absent from the API documentation (it does not appear in files/). What exactly it does and what its default value is has not been established from the code.

### Changes in the game code

**Beastmaster — talents 5/6, `GetAuraRadius`** (server 0x44c8df0 / 0x44c8dd0, client 0x474b7e0 / 0x474b7b0)
- **Before:** `return -1` (global aura).
- **Now on the server:** `GetParent()` (handle at +0x74), then `if byte[+0x16d2] != 0 → 0.0, otherwise −1`.
- **Now on the client:** `GetParent()->vfunc#451`; if true — 0.0.
- **What slot 451 is on a hero** (`C_DOTA_BaseNPC_Hero`): it returns true if the value of modifier property 170 equals 1, otherwise the byte at +0xead. According to enums.json, 170 is `MODIFIER_PROPERTY_IS_ILLUSION`, so the slot is IsIllusion().
- **What +0x16d2 is on the server:** this same byte is checked by the helper function "real hero" 0x4360730 (hero flag and `+0x16d2 == 0`) and by the statistics accounting function 0x5088230.
- **Meaning:** the global +speed/+health auras no longer come from Beastmaster's illusions. According to the localization they are "global, persist through death and affect Beastmaster and all his summoned units".
- **Reliability:** the code — high. That the flag means precisely an illusion — medium-high: on the client it is directly IsIllusion, on the server the conclusion is based on indirect evidence.

**Beastmaster — `GetAuraEntityReject` of the four auras** (Talent_5_Aura, Talent_6_Aura, DrumsOfSlom, InnerBeast_Aura; 0x44c95d0, 0x44c9630, 0x44c9690, 0x44c96f0)
- **Before:** `reject = caster->vfunc#395() != target->vfunc#395()` — comparison of 8-byte pointers.
- **Now:** `reject = caster->vfunc#396() != target->vfunc#396()` — comparison of ints. If there is no caster, the target is still rejected.
- **What the slots are:**
  - 395 (`CDOTA_BaseNPC`/`_Hero::vfunc#395`) — `GetPlayerOwner`. It resolves the owner handle (+0x6bc), walks the chain of heroes and returns the entity if its vfunc +0x548 returned true (by meaning, the player controller).
  - 396 — `GetPlayerOwnerID`. For a hero this is `return [+0x1dd8]`. For other NPCs it is the owner hero's ID, or the field at +0x1014 with flags 0x20100, otherwise −1.
- **Meaning:** the aura selects "units of the same player" by ID, not by controller pointer. The difference will show up where the pointer and the ID diverge, for example when there is no controller. A specific in-game scenario has not been established from the code.
- **Reliability:** the code — high; the interpretation of the slots — medium-high.

**Beastmaster — `CDOTA_Modifier_Beastmaster_InnerBeast::OnIntervalThink`** (0x44f9a50)
- **What it does:** iterates over units with `modifier_beastmaster_inner_beast_aura` and counts those with the same owner. The result is written to +0x1ab4.
- **What changed:** the same 395→396, i.e. the pointer comparison became an ID comparison. The rest is registers and stack frame size.
- **Meaning:** according to the localization of the Wild Hunt facet ("the attack speed bonus grows with the number of units under Inner Beast"), this counter probably sets the bonus. Units with the same owner ID are counted.
- **Reliability:** the code — high; the connection to the facet — medium.

**Beastmaster — `CDOTA_Modifier_Beastmaster_DrumsOfSlom::OnIntervalThink`** (0x452ac80)
- **What the block does:** searches for units in a radius. Each NPC with the same owner gets healed, the particle `phoenix_sunray_beam_friend.vpcf` on `attach_hitloc`, and an overhead message 0xa (`OVERHEAD_ALERT_HEAL`).
- **What changed:** this block existed before — in the diff it is removed in one place and inserted in another. Only the owner comparison changed: 395→396. The overhead message is still addressed via `GetPlayerOwner` (0xc58 remained).
- **Meaning:** Drums of Slom heals "units under his control" (as in the localization), identifying them by player ID.
- **Reliability:** high.

**Hoodwink — `CDOTA_Ability_Hoodwink_Decoy::OnSpellStart`** (0x49404e0)
- **What was added:** after `no_effect_on_original = 1`, `permit_illusion_recycling = 0` is written into the illusion parameter table — the same setter 0x3a34290, `edx = 0`.
- **How others do it:** for other illusions — Phantom Lancer (Juxtapose, Doppelganger, Spirit Lance), Spectre Haunt and others — this key equals 1.
- **Meaning, from the key name:** the Decoy illusion now probably cannot be "reused". This is probably a fix for a bug related to illusion recycling.
- **Reliability:** the fact of the write — high; the meaning — medium-low.

**HUD: map pings** (client 0x59f9e80; called from `CHudDOTABase::vfunc#66`, `CDOTA_Hud_Minimap::vfunc#16`)
- **What changed:** the blocks were rearranged. The sending of `dota_rune_spotted` (userid, rune, rune_team, map_location) remained in the function: xref finds it in the new build at address 0x59fcac2.
- **Send condition:** if the flag is set and more than 2 s have passed since the last time (or the time difference is negative) — the event; otherwise the sound `General.PingRune`.
- **The only formal difference:** with the flag cleared and a negative time difference, the old code could still send the event. In practice this is impossible.
- The `General.PingAttack`/`General.PingDefense` branches were only moved.
- **Reliability:** high (old and new code compared via disasm).

**Death Prophet — `Exorcism::OnIntervalThink`** (0x4554d00, +935 bytes)
- **What is visible in the code:**
  - the pointer to the spirit structure moved from r14 to r10, hence many saves to the stack and restores;
  - the CHandle assignment (constants 0x7fff, 0xf, field +0x30) is now inlined — hence direct calls 181→180;
  - the block "move the spirit's handle to the list at +0x1ae0 and remove the spirit from +0x1af8" was moved unchanged.
- Strings and data constants did not change. This is recompilation.
- **Reliability:** high.

**Ember Spirit — `Activate_FireRemnant::vfunc#371`** (0x492cd20)
- The reverse case: the inline handle assignment at +0x894 was replaced with a function call (55→56 calls, 0x7fff, 0xf, +0x30 disappeared). Plus registers and stack.
- The logic is the same. **Reliability:** high.

**Dawnbreaker — `Solar_Guardian_Thinker::OnIntervalThink`** (0x4939200)
- **What changed:** the manual check "caster is a real hero (flag or vfunc#425) and not +0x16d2" was replaced with a call to the helper function 0x4360730, which performs exactly this check. It is also called by 99 other functions (Rupture, Healing Ward, etc.).
- The result is passed to the statistics accounting function 0x5088230 (id 0x33e, accepts only real heroes), as before. The rest is inline array-expansion code.
- The behavior is equivalent. **Reliability:** high.

**Riki — registration of the client class `C_DOTA_Ability_Riki_Backstab`** (client 0x47b30a0)
- This is a static initializer that computes a key via MurmurHash2 (0x5bd1e995 and others are MurmurHash constants, not cryptography).
- The second call of the hash function was replaced with inline rounds with constants 0x3c798d9f and 0xde45aed5.
- Whether the key value changed and what that means is unclear. This does not point to any change in Backstab's game logic: Riki's server code did not change.

**Courier — `CDOTA_Unit_Courier::Spawn`** (0x454af60)
- The vector of a single value 0x1c7c, passed to vfunc +0xe8, is now built from an initializer list rather than via push.
- Recompilation. **Reliability:** high.

**Bot — `CDOTA_BotMode_Farm::vfunc#10` (GetDesire)** (0x5dfe860)
- The read of `[r12+0xd8]` was moved, but in both the old and the new code the comparison is against the value after the call.
- Equivalent. **Reliability:** high.

- **Only `libclient.so` and `libserver.so` changed.**
