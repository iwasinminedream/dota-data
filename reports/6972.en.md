# Dota 6972: what changed

The report was generated automatically on 2026-11-16. The draft covering all changes (parts: 1) was produced by Claude Sonnet 5.5, and the verification against source data and the final version by Claude Sonnet 5.5 (read-only access); the tables below were calculated without a model.

## Summary

### Highlights

- According to the data, there are no real game changes. `api-changes.txt` contains a single line: the member `ACT_DOTA_CAST5_STATUE` = 1798 was added to `GameActivity_t` (`+1 -0 ~0`). The other files (`func-diff.txt`, `so-diff.txt`, `tracking-diff.txt`) are absent, so no game code can be seen from them.
- This is most likely an artifact of an unstable dumper, not a new mechanic.
  - In `dump-noise.md`, two dumps of the same build (6972, build 26466928) diverge precisely in the `cl_script_reload` constants block: for `ACT_DOTA_CAST3_STATUE`, `CAST4_STATUE`, `CHANNEL_STATUE`, `DEFEAT_STATUE`, `DISABLED_END` and `battlemaiden_debut_truncated` the values jump by one.
  - `ACT_DOTA_CAST5_STATUE` itself is not named in this noise table. But in `files/changelogs/` it is mentioned in 33 files, meaning it keeps appearing and disappearing.
  - In 6971 (November 3, 2026) it was removed with the same value 1798, and in 6972 (November 5) it was added back. In other versions the values were 1794, 1795, 1800, 1805.
  - The conclusion about the dump's instability is reliable, because it follows from the changelog history. What exactly in the dumper causes these jumps cannot be seen from the data.
- Nothing changes for custom games. You get the "CAST5 for statue" activity animation or not depending on whether it made it into the dump.

### New properties and methods: what they do

- **`ACT_DOTA_CAST5_STATUE` = 1798** (a `GameActivity_t` constant, not a method or property).
  - **What it is.** By its name, it is the fifth "cast" animation for a statue model, in the series `ACT_DOTA_CAST1_STATUE` … `CAST4_STATUE`. Nearby there are other `*_STATUE` constants: `IDLE`, `RUN`, `ATTACK`, `STUN`, `SPAWN`, `TAUNT`, `DEFEAT`, `CHANNEL`. This is an inference from the name and neighbors, not from code: `strings`/`xref` on the `.so` would give more, but `so-query` did not run in this directory ("no so-query.json here"), and there are no `.so` snapshots for 6972.
  - **How to use it.** It can be passed wherever `GameActivity_t` is accepted: `StartGesture`, `StartGestureWithPlaybackRate`, `ACT_*` in KV and in the `OVERRIDE_ANIMATION` modifier. The model must contain the corresponding sequence. It is not advisable to rely on it in a custom game: the constant is sometimes in the dump and sometimes not.
  - **Evidence.**
    - Dump: `dumper/dump` (line 31714) and `files/vscripts/enums.json` (line 9175, the last member of `GameActivity_t` after `ACT_DOTA_CHANNEL_STATUE` = 1796) contain it with 1798. It is absent from `previous-dump.txt`.
    - The adjacent `ACT_DOTA_CAST4_STATUE` (1797) and `CAST3_STATUE` (1794) are not exported in `files/vscripts/enums.json`, only `DEFEAT`, `CHANNEL` and `CAST5` are.
    - The other `*_STATUE` constants are present in the dump.
    - There are no localizations or KV associated with this constant.
  - **Reliability.** The addition to the dump itself is confirmed. What it means in the game is unclear, and the value 1798 and the very fact of its presence are unstable.

### For custom game developers

- There are no new, removed or changed Lua API methods, Panorama functions, events, modifiers or console variables. This is confirmed by the only section of `api-changes.txt` ("API Lua Enums: +1 -0 ~0").
- What may break: nothing new. The numeric values of `ACT_DOTA_*_STATUE` (and the neighboring `ACT_DOTA_DISABLED_END`, `battlemaiden_debut_truncated`) change between dumps by 1–5. Do not hardcode these numbers into data; use the `ACT_*` names.
