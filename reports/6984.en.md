# Dota 6984: what changed

The report was generated automatically on 2026-11-19. The draft covering all changes (parts: 4) was written by Claude Sonnet 5.5; the check against source data and the final version were done by Claude Sonnet 5.5 (read-only access); the tables below were calculated without a model.

## Summary

### Highlights

- **Build 6983 → 6984** (SourceRevision 11256873 → 11257680, November 19, 2026). The patch is technical: there is no new content (heroes, items, assets) in the data. The main change is in the Lua modifier engine.
- **Lua modifiers now receive 89 properties and events that the engine previously never called.**
  - In `modifier_properties.json`, the HasFunction flag changed from `false` to `true` for 89 entries.
  - Exactly 89 wrappers of 36 bytes each were added to both libclient and libserver. Each contains the name of a Lua callback (`GetModifierSpellRedirectTarget`, `OnTreePlanted`, etc.) and is called from the Lua modifier dispatcher.
  - The upper bound of the property index in the dispatcher was raised from `0x191` (401) to `0x1a0` (416) = `MODIFIER_FUNCTION_LAST` − 1.
  - Previously, all properties and events with id > 401 never reached Lua. Among them are `ON_TREE_PLANTED`=410, `ATTACK_POTENCY`=413, `HEALTHBAR_PIPS_FRAGILE`=416.
- **Typos in callback names were fixed.**
  - Was `GetModifierPropetyFailAttack(event)`, now `GetModifierPropertyFailAttack()`.
  - Was `GEtModifierSlowResistance_Unique`, now `GetModifierSlowResistance_Unique`.
  - For `INCOMING_DAMAGE_CONSTANT_POST` (303), instead of "description = constant name", the method `GetModifierIncomingDamageConstantPost` appeared.
  - For `INCOMING_DAMAGE_ILLUSION` (276), the method `GetModifierIncomingDamageIllusion` appeared.
- **Sniper — Headshot.** The single "last throw succeeded" flag (`m_bLastRollSuccess`) was replaced with a list of attack record ids `m_vecSuccessfulRolls`. A new event `ON_ATTACK_RECORD_DESTROY` was added, which clears this list.
- **Enchantress — Impetus.** The attack animation change (translate activity) became conditional. For 5 activities it is applied only if Impetus actually triggers. The event `ON_ATTACK_FINISHED` was added on the client and on the server.
- **Meepo — Fling Held.** A held Meepo gets the states `UNSELECTABLE` and `UNTARGETABLE`.
- **Meepo — Geomancy.** The lookup of the ability `meepo_divided_we_stand` was moved from `OnCreated` to `OnIntervalThink`.
- **Other code changes.** Notable logic changes are in Caduceus (the last argument of the modifier-application call 0→1), Mind Breaker and Chen (the Zealot aura). The remaining differences in functions are recompilation or code moved between functions.

**Native modifiers (api-changes: +5)**

- **`modifier_enchantress_impetus` — `MODIFIER_PROPERTY_TRANSLATE_ACTIVITY_MODIFIERS`** (on the client the formula appeared, on the server it changed; the client `vfunc#112` grew from 86 to 519 bytes, the server `vfunc#128` from 20 to 83 instructions).
  - The handler responds to activities 1503, 1504, 1505, 1705 and 1758 (codes `0x5df…0x5e1`, `0x6a9`, `0x6de`, event field `+0xc` = `activity`). Previously it unconditionally returned the string `"impetus"`.
  - Now `"impetus"` is returned only if: the unit has no `modifier_phantom_assassin_stiflingdagger_caster`; the unit is not silenced; there is enough mana (`GetEffectiveManaCost` is not greater than current mana); Impetus is not on cooldown; and either the ability is being cast right now, or autocast is enabled.
  - Basis: the formula in `native_modifiers.json` and the disassembly of `0x47f80d0`. Reliability is high. Meaning: the Impetus attack animation is not enabled when there will be no shot.
- **`modifier_enchantress_impetus` — `MODIFIER_EVENT_ON_ATTACK_FINISHED`** (server only). An entry `+0x11d0` appeared in the property table, and the new function `0x4805f50` serves it. It takes the attacker, checks the alive flag (`+0xd3c & 1` and the virtual slot `#427`) and calls a function containing the string `CNetworkTransmitComponent::StateChanged`. This is probably a network-state mark for recalculating the animation. Reliability is low: the call target is not revealed.
- **`modifier_sniper_headshot` — `MODIFIER_EVENT_ON_ATTACK_RECORD_DESTROY`.** An entry `+0x1250` appeared in the property table. The handler is the new function `0x4731710` (from `vfunc#97`):
  - takes the attack record id (`event+0x44`, 16 bits);
  - looks for it in the array `+0x1b18` (2 bytes per element);
  - if found, replaces it with the last element and decreases the size.
  
  This is cleanup of `m_vecSuccessfulRolls` so that successful throws do not accumulate. Reliability is high (the code was read in full).
- **`modifier_meepo_fling_held` — `MODIFIER_STATE_UNSELECTABLE` (14) and `MODIFIER_STATE_UNTARGETABLE` (37).**
  - `CheckState` on the client (`0x4b8df80`) and on the server (`0x4b207f0`): the "enable" mask `0x800022 → 0x2000804022`; the "do not touch" mask `0xffffffffff7fffdd → 0xffffffdfff7fbfdd`. Bits 14 and 37 were added.
  - The numbers were checked against the dump (`MODIFIER_STATE_UNSELECTABLE`=14, `MODIFIER_STATE_UNTARGETABLE`=37).
  - Gameplay meaning: a Meepo held during Fling cannot be selected and cannot be targeted. Reliability is high.

**Other new names from the .so and the schema**

  - In practice this means that Headshot now accounts for several attacks in flight at once, not just the last one. This is an inference from the code structure; behavior in combat was not verified.
- **Sound `Hero_ChaosKnight.ChaosStrike`.** In `0x4a6ede0` (called from `ArcWarden_TempestDouble::vfunc#97`), the string `Hero_ChaosKnisght.ChaosStrike` was replaced with `Hero_ChaosKnight.ChaosStrike`. ### For custom game developers

- **The behavior of existing addons may change.**
  - If your Lua modifier already returned any of the 89 properties or events from `DeclareFunctions` (list above), it was silently ignored before. Now it is called and applied.
  - Check modifiers written "in advance" or copied from other projects.
  - Pay special attention to those that depend on `FAIL_ATTACK`, `INCOMING_DAMAGE_CONSTANT_POST`, `PREREDUCE_INCOMING_DAMAGE_MULT`, `REPLACE_ATTACK`, `BECOME_*`, `FORCE_MAX_HEALTH` / `FORCE_MAX_MANA`, `ON_ORDER_RECEIVED`, `ON_MODIFIER_REMOVED`, `ON_TREE_PLANTED`.
- **Renames.** The method `GetModifierPropetyFailAttack` (with a typo) has been removed from the API. Use `GetModifierPropertyFailAttack`. The old name was not called before anyway (the flag was `false`), so nothing breaks, but it won't start working either. Likewise `GEtModifierSlowResistance_Unique` → `GetModifierSlowResistance_Unique`.
- **The "method" `MODIFIER_PROPERTY_INCOMING_DAMAGE_CONSTANT_POST(event)` has been removed.** It was a description of a constant formatted as a method, not a real callback. Use `GetModifierIncomingDamageConstantPost`.
- **The enum `ACT_DOTA_LOADOUT_STATUE = 1801`** in the api-changes row is dumper noise. In the control dump of the same build, the `cl_script_reload` value jumps 1801↔1807, and the `ACT_DOTA_*` numbering gets shuffled. Do not treat this as a change; do not hardcode the numeric values of `ACT_DOTA_*`.
- **Dumper noise.** The "LUA Memory usage warning…" warning and the `ACT_DOTA_*` shifts (`CAST3_STATUE`, `CYCLONE`, `IMPALE`, `TORRENT`, `RELAX_IN/OUT`, `RUN_ALT`, `ACT_DOTA_SPWN`, the disappearance of `CAST5_STATUE`, etc.) reflect dumper instability, not the game.
- **Native modifiers (65 "~" in api-changes): almost all are replacements of flag literals with constant names** in the decompilation of formulas. The logic does not change. Examples: `damage_flags & 32` → `DOTA_DAMAGE_FLAG_HPLOSS`, `& 16` → `DOTA_DAMAGE_FLAG_REFLECTION`, `& 1024` → `DOTA_DAMAGE_FLAG_NO_SPELL_AMPLIFICATION`, `& 4` → `BYPASSES_INVULNERABILITY`, `& 131072` → `MAGIC_AUTO_ATTACK`, `& 48` → `REFLECTION | HPLOSS`, `damage_category & 1` → `DOTA_DAMAGE_CATEGORY_ATTACK`, `damage_type ~= 1/2` → `DAMAGE_TYPE_PHYSICAL/MAGICAL`.
  - Shields, barriers and damage percentages are affected: Abaddon Aphotic Shield, Bristleback, Centaur Stampede, Crystal Maiden Frostbite, Doom, Lich Frost Shield, Nyx Burrow/Spiked Carapace, Ursa Enrage, Wisp Tether, Zeus Thunder Trail, Bloodstone, Veil of Discord, Gale Guard, Martyr's Plate, Faceless Void Backtrack, Juggernaut Duelist, Kez Parry, Spectre Dispersion, Treant Living Armor, Tinker Defense Matrix, etc.
  - For `modifier_item_invisibility_edge_windwalk` (client) only the address in the formula changed (`6539194776` → `6539202968`) — this is a recompilation.
  - `modifier_sniper_keen_scope` (client) changed in the tail of the expression, with no visible change in logic.
  - Real behavioral changes among the "~": Impetus and Sniper Headshot (described above).
- **Panorama, console variables, game events, KV API (`abilities.json`, `units.json`):** no changes according to the data.
- **The Lua modifier dispatcher on the client and server** (`CDOTA_Modifier_Lua::vfunc#88` and `vfunc#97`) now serves indices up to 416. For custom games this means that all `MODIFIER_PROPERTY_*` and `MODIFIER_EVENT_*` up to `MODIFIER_FUNCTION_LAST` (417) have gained a call path into Lua.

### Changes in game code

- **`CDOTA_Modifier_Meepo_Fling_Held::CheckState`** (client `0x4b8df80`, server `0x4b207f0`) — states 14 and 37 (see section 2). Confidence is high.
- **`CDOTA_Modifier_Meepo_Geomancy`.**
  - The old `OnCreated` (`0x4b33060`, 140 bytes) found the ability `meepo_divided_we_stand` on the owner and saved its handle in `+0x1b18` (otherwise `-1`). It also checked the virtual slot `#356` (`+0xb20`) and skipped the search if the result was nonzero.

  - Failure conditions were added: byte `+0x175a ≠ 0`, byte `+0xd8d ≠ 0`.

  - In KV, `chen_zealot` is an innate ability ("Only 1 Zealot may exist at a time" in the localization). Apparently, the aura is no longer applied to targets that already received the buff from another source.
  - Which exact entities stand behind the bytes `+0x175a` and `+0xd8d` is not established from the data. Confidence is medium.
  - The related function `0x4868c70` (from `Chen_Zealot::OnHeroLevelUp` and `OnAbilityUpgrade`): the only change is the argument `push 0x12` → `push 0x13`. The meaning of the number is not determined.

  - In `0x628d070`, with `duration > 0` and the flag `0`, a branch runs with a team check (`+0x624`) and a key from the data next to the string `counts_as_debuff`. With the flag `1` this branch is skipped.
