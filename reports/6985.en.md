# Dota 6985: what changed

The report was generated automatically on 2026-11-19. The draft of all changes (parts: 5) was written by Claude Sonnet 5.5; the check against the source data and the final version were done by Claude Sonnet 5.5 (read-only access). The tables below were calculated without a model.

## Summary

### Key points

- **There is no Lua API diff (+217 / −1780) or enum diff (−500) in the game; this is a dump failure.** In the new `dumper/dump` the line `LUA Memory usage warning…` ended up inside the JSON of the server section `script_reload` (line 1083). In the previous dump it was in the client section after `...done`. The rest of the dump contents match in size and in section offsets (offsets shifted by +1 line, 29809→29810, etc.). The server JSON apparently failed to parse, and `build/vscripts/dump.ts` fell back to the client dump: there `try { JSON.parse(readDump('script_reload')…) } catch { serverDump = clientDump }`. As a result, only the client `C_*` classes "appeared", while the server classes, functions and enums "disappeared". I did not run the build, so the mechanism is inferred from the code and the dumps: confidence is high, but not absolute. **The current `files/vscripts/api.json` and `enums.json` for 6985 must not be used.** `api.json` contains `C_BaseEntity` and `C_DOTA_BaseNPC`, but the server `CBaseEntity` and `CDOTA_BaseNPC` are missing.
- **The real update is small.** This is build 6984→6985 (SourceRevision 11257680→11258601). The code grew by +256 bytes in `libclient.so` and by +768 in `libserver.so`. One new string in each library.
- **Chaos Knight, Armageddon.** The abilities `chaos_knight_armageddon` and `chaos_knight_armageddons_flank_end` already existed in the game. Three things changed:
  - the modifier `Armageddon_Phantasms` can no longer be removed by a dispel (`IsPurgable`: 1→0, both libraries);
  - `Phantasm` got its own `GetAssociatedSecondaryAbilities`, which returns the string `chaos_knight_armageddon;chaos_knight_armageddons_flank_end`;
  - the particle `chaos_knight_armageddon_ribbon` was removed from the VPK, and `chaos_knight_armageddon_charge` and `…_charge_active` were changed.
- **Venomancer, Snakebite.** The attack penalty for an infected unit's attack now also skips `luna_moon_glaive` (previously only `luna_lunar_orbit`).
- **The remaining ~100 changed functions** are recompilation: shifts of jump table and rodata addresses, inlining and devirtualization. Individual items where the logic may have changed are covered in the game code section. Among them is Disruptor (Kinetic Field and Thunder Strike).
- `patchnotes.vdpn_c` and `patchnotes_english.txt` were changed in the VPK. The repository search (grep for `tracking/vpk/dota/patchnotes.txt`) did not find the patch notes text by ability name, so the conclusions were not checked against it.

### New properties and methods: what they do

**There are no confirmed new properties, events, Lua API methods or Panorama in 6985.**

- **`C_*` classes and methods** (`C_BaseEntity.GetAbsOrigin`, `C_DOTA_BaseNPC.*`, `C_DOTA_Ability_Lua.*`, `C_DOTAPlayerController.GetQueryUnit` and others, 217 entries).
  - This is not new API but the client part of the Lua API. Previously it did not make it into `api.json`, and now it did because of the fallback to the client dump.
  - These methods already existed on the client. `GetHeroFacetID` simply "moved" from `CDOTA_BaseNPC_Hero` to `C_DOTA_BaseNPC_Hero` in this artificial diff.
  - Evidence: the dump (position of the noise line) and `dump.ts`. Confidence is high.
- **The only real novelty in the code is the override of `GetAssociatedSecondaryAbilities` in `CDOTA_Ability_ChaosKnight_Phantasm`.**
  - Slot `#382` in `libserver.so` (in the client `C_DOTA_Ability_ChaosKnight_Phantasm::vfunc#358`). That slot `#382` is `GetAssociatedSecondaryAbilities` can be seen from `so-query vtable` for `CDOTA_Ability_Lua`, where the slot is named.
  - A 29-byte function calls a helper and returns a pointer to the string `chaos_knight_armageddon;chaos_knight_armageddons_flank_end`. If the helper returned true, it returns null.
  - `Chaos_Knight_ArmageddonsFlank_End` already had the same slot `#382`, returning `chaos_knight_armageddons_flank`. So the mechanism is old, and Phantasm now also lists linked abilities. Custom games do not need this.
  - What the helper (`0x5405cd0`) checks: it compares the field `+0x484` of a global object with `0x12`, otherwise reads the byte `+0x58`. I did not establish the meaning of the condition.
  - The conclusion about the slot's purpose (linking abilities in the interface and draft) is by analogy with `Flank_End`. Confidence is medium.

### For custom game developers

- **Do not publish or use `files/vscripts/api.json`, `api.d.ts`, `enums.json`, `enums.d.ts` for 6985.** Otherwise `CBaseEntity`, `CDOTA_BaseNPC`, `CDOTABaseAbility`, `CDOTA_Ability_Lua`, `CDOTA_Item_Lua`, `CDOTAGameRules`, `ApplyDamage`, `CreateUnitByName`, `DOTA_UNIT_ORDER_*`, `DOTA_ITEM_SLOT_*`, `DAMAGE_TYPE_*`, `DOTA_MODIFIER*` and 466 members of 34 enums will disappear, and the types will be simplified to `handle` and `unknown`. The dump needs to be regenerated (remove the line `LUA Memory usage warning…` or strip it in `dump.ts` the same way as `reloadMessage`) and rebuilt. The noise is recorded in `dump-noise.md`.
- **Nothing breaks for existing addons.** There is no real API removal: the server dump contains `CDOTA_BaseNPC` (line 23839) and the other classes, as in 6984.
- **Modifiers, console variables, events, Panorama.** In `tracking-diff.txt` there are no schema changes, `.proto`, `scripts/`, `items_game`. In `api-changes.txt` there are no changes to Panorama or cvars.
- **Gameplay changes visible to custom games with Dota heroes:**
  - Armageddon_Phantasms cannot be dispelled;
  - Moon Glaive does not trigger the Snakebite penalty (details in the next section).

### Game code changes

Total: `libserver.so` — 93 changed, 2 added, 5 removed; `libclient.so` — 16 changed, 1 added. Full list: `so-query.py funcs libserver.so` and `so-query.py funcs libclient.so`. The file `reports/6985-functions.md` is not in the working directory.

**Real logic changes**

- **`CDOTA_Modifier_ChaosKnight_Armageddon_Phantasms::IsPurgable`** (server `0x49fe3a0`, client `0x4ae57c0`): `mov eax,1` → `xor eax,eax`. The modifier cannot be removed by a dispel. Basis: code diff, 2 instructions, both libraries. Confidence is high.
- **`CDOTA_Ability_ChaosKnight_Phantasm::GetAssociatedSecondaryAbilities`** (added, server `0x4a213f0`, client `0x4afcc20`): see above.
- **`CDOTA_Modifier_Venomancer_Snakebite::vfunc#97`** (`0x4744a50`, 669→740 bytes).
  - This is the "attack penalty" handler: for an infected unit, a string with an ability name is checked.
  - Previously, if the name was `luna_lunar_orbit`, the handler exited without a penalty. Now the same applies to `luna_moon_glaive`; an empty name is replaced with `<NoAbilityName>`.
  - Snakebite localization: "When the target attacks while infected, they take the initial damage again". This means Moon Glaive attacks do not repeat the initial damage.
  - Whose field this is (`+0x840` of the object found via the attack record) was established by analogy with other functions. Confidence: the fact of comparison with the name is high, the interpretation "Moon Glaive attacks" is medium.

**Possible changes (meaning unclear)**

- **`CDOTA_Modifier_Disruptor_KineticWall_Thinker::OnIntervalThink`** (`0x4a8d0b0`).
  - The ability `disruptor_electromagnetic_repulsion` is looked up as before.
  - Checks of two boolean fields (`+0x7e0`, `+0x7e1`) and branches on `null` appeared. A call that previously ran unconditionally is now executed only when the flags are set.
  - It looks like additional pushback conditions at the Kinetic Field wall. I did not determine which ones. KV did not change. Confidence is low.
- **`CDOTA_Modifier_Disruptor_Thunder_Strike::OnIntervalThink`** (`0x4adfdf0`).
  - The call with code `0x227` (the meaning of the code is not established) under the condition "counter > 1" remains, but is now executed only if the target is not null, `[+0x5d1]==3`, bit 0 of `[+0xd3c]` is cleared and the virtual method `+0xd58` is the base one.
  - This is a refinement of the target (for example, filtering out non-units), but which one exactly is unclear. Confidence is low.

**Recompilation and inlining (logic unchanged)**

- **`CDOTA_Ability_WitchDoctor_DeathWard::vfunc#156`** (`0x47816b0`, 1043 bytes). This is not new logic, although the draft says so.
  - The automatic "was" pair (`0x47815f0`) was taken by mistake: it is shared helper code of `NetworkStateChanged`. The real old version is the removed `0x4790260` (470 bytes).
  - Both versions do the same thing: check the handle `[+0x85c]` and the timer `[+0x870]`, then reset them to `-1` and move the next call to "time+5".
  - There is one difference: `CNetworkTransmitComponent::StateChanged` is now inlined directly into the function instead of being called.
- **Devirtualization and inlining.** `RollingBoulder::vfunc#371` (comparison with `npc_dota_earth_spirit_stone`), `Underling_Spawn_Thinker` (`0x4acd5c0`, the substitution of `<NoAbilityName>` in the comparison with `grimstroke_ink_creature` was removed), `CDOTA_BaseNPC_Hero::vfunc#263` (`dota_player_take_tower_damage`), `Kez_GrapplingClaw::vfunc#334`, `CDOTA_Unit_TargetDummy::vfunc#263`, `CDOTA_RoshanSpawner::vfunc#237`, `CDOTA_BaseNPC_Creep_Neutral::vfunc#351` and `CDOTA_Neutral_Creep_BehaviorController::vfunc#3`.
  - In the last two, the code of the base implementation is embedded instead of a virtual call: `byte [+0x790]=0`, `dword [+0x794]=-1`. This is not a new reset, but a replacement of `call rax` with a "method not overridden" check plus the body.
- The rest of the server: `0x5c02920` (`npc_dota_mutation_pocket_roshan`, a traversal of 24-byte entries was added); `0x5c1c1b0` (the call now returns bool instead of float); `0x56b21b0` (the removed `0x56b2100` is baked into it); `0x6280100`; `BackdoorProtectionInBase::vfunc#9` (an unreachable `ud2` was added); `0x4e30bd0` and `0x4f4bc80` (rebuild of `CDOTA_Item_EmptyBottle`). For each of them, "logic unchanged" is not fully proven: some of the diffs were truncated by the tool, but there are no gameplay indicators (strings, data constants). Confidence is medium.
- **Client.** `CDOTA_Unit_Hero_AbyssalUnderlord::vfunc#149` (`0x4b46190`, Dark Portal indicator, `minimum_distance` and `range_finder_tower_aoe.vpcf`): building the particle structure on the stack was replaced with a function call, and the handle is resolved by a call instead of inline. The constant 100.0 (`0x42c80000`) and the particle string remain. Confidence: refactoring, medium. Two more unnamed functions: `0x4b477f0` (three lazy static initialization blocks removed) and `0x5e2db40` (initialization moved out into `0x5e2dab0`). Also recompilation.
- **Shift of jump tables and rodata** (only the address of `lea` changed; 12 functions in the client, about 60–70 in the server): a series of KV3 serializers `0x3c275e0…0x3c29c20`, `CTakeDamageInfo` (`0x3d98d10`), `CBaseLightProbeVolume::vfunc#2`, `CNetworkTransmitComponent::vfunc#3`, `CHitboxComponent::vfunc#4` and so on. There is no logic in them.
- **Copies of existing code** (not changes): 2 in the client, 8 in the server, including trivial `ArmageddonsFlank_End::vfunc#345/#384/#387`.
- **Added or removed other than the above:** `0x3e6ee50` was added (98 bytes, a schema helper), three small schema helpers (`0x3e6ebb0`, `0x3e6ece0`, `0x3e6ee80`) and `0x56b2100` were removed. The meaning of the schema helpers is not established.
